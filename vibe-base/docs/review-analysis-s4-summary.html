競合との最大の差異

全4社（口コミコム/Location Connect/MEOチェキ/Gyro-n）がAWS自社運用型。当社のみVercelサーバーレス型。

競合が「やらない」のではなく「この価格帯ではAWSの固定費が採算に合わない」。サーバーレス選択が¥980/月の価格設定を可能にする構造的根拠。

マスター確認事項

❶ Google Places API — 1リクエスト最大5レビュー制限

「全クチコミを分析」という訴求は、Places APIだけでは実現できません。

MVPの対処: 新着レビューを定期取得（例: 1日1回）→ DB蓄積。時間をかけて履歴を構築する方式。

将来: Google Business Profile API（オーナーのOAuth認証で全レビュー取得可能）へ移行。

LP訴求への影響: 「全クチコミを一括分析」とは書けない。「新着クチコミを自動で分析」が正確な表現。

❷ Gemini無料枠 — クチコミデータがGoogleに利用される

Gemini API無料枠では、入力データ（=顧客のクチコミ）がGoogleのモデル改善に利用されます。

対処: S5コスト発生マップに「Gemini有料API移行」の閾値を含める。有料APIではデータ利用なし。

閾値目安: 有料でも入力$0.30/1Mトークン。クチコミ1件≒200トークンとして、1,000件/月でも$0.06。コスト影響は軽微。むしろ「データを送らない」選択肢（ローカルモデル）は現実的でない。

❸ Vercel Pro $20/月 — 許容しない場合の3パターン

Vercel Hobbyプラン（無料）は商用利用不可（利用規約で明記）。飲食店向けSaaSとして提供する時点でProが必要。

許容しない場合、以下の3パターンがあります。

パターンA: Railway $5〜15/月

Dockerコンテナベースのホスティング。Next.jsをコンテナとしてデプロイ。

月額$5/月 + CPU/メモリ従量。中規模で$8〜15/月
デプロイ方法railway up or GitHub連携（自動デプロイ）
失うものISR（Incremental Static Regeneration）/ Edge Functions / Fluid Compute / Image Optimization API / Vercel Analytics
DB影響Neon継続可。Vercel統合なしだがConnection String直指定で問題なし
監視影響Sentry継続可。Vercel Analytics → 別途GA4で代替
利点
  • Vercelの1/2〜1/3のコスト
  • Docker標準なのでベンダーロックインが弱い
  • バックエンドサービスを同一プロジェクトに追加しやすい
リスク
  • Next.js最適化なし（初回ロード遅延。体感-200〜500ms）
  • エッジ配信なし（東京リージョンのサーバー1台のみ）
  • Next.js App Routerの一部機能で非互換の可能性
  • Image Optimization自前実装が必要（sharp）

パターンB: Coolify + Oracle Cloud Free Tier $0/月 運用コスト高

Oracle Cloudの永久無料ARM枠（4 OCPU / 24GB RAM）にCoolify（セルフホストPaaS）を構築。

月額$0（Oracle Cloud Always Free Tier）
スペックARM Ampere A1: 4 OCPU, 24GB RAM, 200GB Block Volume（無料枠上限）
CoolifyとはオープンソースのセルフホストPaaS。Vercel/Railway相当のデプロイ体験をVPS上で再現
デプロイ方法GitHub連携 → Coolify経由で自動ビルド+Dockerデプロイ
失うものVercel全機能（ISR/Edge/Fluid Compute/Analytics）+ 自動スケーリング + CDN
補完策Cloudflare（無料）をフロントに配置してCDN/DDoS防御を確保
利点
  • 完全$0。 開発コスト¥0制約を文字通り達成
  • スペックが潤沢（24GB RAM。Vercel Proの数十倍）
  • DB（PostgreSQL）もサーバー内に同居可能（Neon不要）
  • Coolifyがgit push→自動デプロイを提供
リスク
  • インフラ管理が全て自分。 OS更新/セキュリティパッチ/障害対応
  • Oracle Cloud Freeは予告なしのインスタンス回収リスクあり（idle時）
  • ARM（aarch64）対応のDockerイメージが必要（Next.jsは対応済み）
  • 東京リージョンでFree枠が確保できない可能性（人気で枯渇報告あり）
  • スケーリングは手動。トラフィック急増に弱い

パターンC: Cloudflare Pages + OpenNext $0〜5/月

OpenNextアダプタでNext.jsをCloudflare Pages/Workers上に変換デプロイ。

月額Pages Free: $0（無制限リクエスト）。Workers有料: $5/月（10M req含む）
OpenNextとはNext.jsをVercel以外にデプロイするためのOSSアダプタ（SST開発。AWS/Cloudflare対応）
デプロイ方法opennextjs-cloudflare → wrangler pages deploy
CDNCloudflareグローバルネットワーク（東京PoP含む300+拠点）。Vercel以上
対応状況Next.js App Router対応。Server Actions/ISR/Middleware対応済み。ただし一部エッジケースあり
失うものFluid Compute / Vercel Analytics / Vercel独自の最適化
利点
  • Free枠でも無制限リクエスト。ほぼ$0運用可能
  • CDN性能はVercel以上（300+拠点）
  • DDoS防御/WAFがデフォルト
  • Workers KVやD1（SQLite）など追加ストレージも無料枠あり
リスク
  • OpenNextは成熟途上。 Vercel前提のNext.js機能で非互換が出る可能性
  • Workers実行時間制限: Free=10ms CPU / Paid=30s。API処理が重いと制限に抵触
  • Gemini API呼び出し（AI分析/返信生成）はCPU時間制限との相性が悪い
  • デバッグが難しい（Vercelのログ/プレビュー機能がない）
  • Prisma + Neon接続がWorkers環境で追加設定必要（@prisma/adapter-neon）

補足: 当プロダクトはAI分析（Gemini API呼び出し）がコア機能のため、API Routes内で数秒の処理時間が発生します。パターンCのCloudflare Workers CPU時間制限（Free: 10ms / Paid: 30s）はこの処理と相性が悪く、有料プランでも制約になる可能性があります。パターンA（Railway）が現実的な妥協点です。
