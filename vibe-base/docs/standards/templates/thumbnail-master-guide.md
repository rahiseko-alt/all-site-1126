## 5つの黄金律

### 1. 構図 — 中央集約型（単一ゾーン）

**v2.0 で採用した中央集約型の根拠**

縦長サイズ（1220×1240）では左右二分割が機能しない。理由は2つ:

1. 縦方向に長いため、二分割すると左右どちらのゾーンも縦に間延びして読みにくい
2. ココナラでは縦長カードUIで表示されるため、視線は上→下に流れる（左→右ではない）

そのため、**全要素を中央配置し、上から下への垂直方向の優先順位**で構成する。

| 原則 | 適用 |
|---|---|
| 視線誘導 | 上 → 中央 → 下（垂直方向） |
| 中央配置 | flex column / align-items: center |
| 余白配分 | 左右 padding 56px / 上下 padding 80px / 中央寄せ |

**例外（横長サイズを使う場合）:**
横長16:9（例: バナー / OGP画像）の案件では v1.0 の左55%右45%構図が依然有効。横長案件のお手本として将来 vest1 #28 を作る可能性あり（現時点では #26 v2.0 が縦長専用）。

---

### 2. 配置 — 重要な要素ほど上に、大きく

サムネイル内の各要素は上から下へ優先順位順に配置する。理由は2つ:

1. 視線は上から下に動くため、上にある情報ほど先に認識される
2. プラットフォームによっては下部にタイトルや価格が重なるため、下部に重要情報を置くと隠れるリスクがある

**お手本（v2.0）での配置順**

| 位置 | 要素 | 役割 |
|---|---|---|
| 上 | ラベル「DSL納品 / すぐに使える」 | カテゴリの即時認識 |
| 上中央 | キャッチコピー（2行） | 最も伝えたいメッセージ |
| 中央 | 価格「4,000円」 | 視線を止めるアクセント |
| 下 | サブコピー（縦線+説明） | 補足情報で安心感を与える |

---

### 3. 文字数 — 15文字以内の原則

キャッチコピーは15文字以内が鉄則。スマホの小さな画面で認識される前にスクロールされることを防ぐため。

**お手本（v2.0）での文字数**

| テキスト | 文字数 | 判定 |
|---|---|---|
| AIチャットボットをあなたのサイトに | 16文字 | △（2行分割で許容） |
| 4,000円 | 5文字 | ⭕ |
| DSL納品 / すぐに使える | 11文字 | ⭕ |
| Dify構築済みDSLをお渡し / インポートするだけで即稼働 | 25文字 | ⭕（サブコピーは制限なし） |

キャッチコピーは厳密には16文字だが、**2行に分割して表示しているため視認性は確保**。理想は15文字以内だが、2行分割で1文字程度の超過は許容範囲。

**フォント原則**
- 太めのゴシック体を使う
- 明朝体は縮小表示で線が潰れるため**使用禁止**
- お手本は `M PLUS Rounded 1c` ExtraBold（900）
- 丸ゴシック系は「親しみやすさ」を演出でき BtoC との相性が良い

---

### 4. 配色 — 70:25:5 の法則と3色ルール

配色は3色以内に抑える（白はコントラスト確保用として独立扱い、4色目とは数えない）。色が増えるほど視認性が落ち、何が重要かわからなくなる。面積比率は **70:25:5（ベース:サブ:アクセント）** が基本。

**お手本（v2.0）の配色設計**

| 役割 | 色 | コード | 比率 | 意図 |
|---|---|---|---|---|
| ベース | ダークパープル | `#3b1d60`〜`#723fa2`（4段グラデ） | 約70% | 先進・知性・AI感の演出 |
| サブ | バイオレット | `#a78bfa` | 約25% | テクノロジー感+背景グロー装飾 |
| アクセント | ゴールド | `#fbbf24` | 約5% | 価格のみに使い、視線を止める |
| 文字白 | ホワイト | `#ffffff` | コントラスト | 独立扱い |

**補色関係**
パープル（270°）とゴールド/イエロー（45°〜60°）は色相環上で**補色に近い関係**にあり、互いを引き立て合う。価格の「4,000円」にゴールドを使うことで、暗い背景の中でも強い視線誘導力を持つ。

**コントラストの確保**
背景が暗い場合、文字は白または明るい色でコントラスト比を十分取る。お手本はダークパープル背景に白文字、最重要の価格部分はゴールドで更にコントラストを強めている。背景と文字のコントラストが弱いと、スマホで文字が読めなくなる。

**v2.0 で確立した重要原則: アクセント色を分散させない**

「AI」等の強調文字をアクセント色（ゴールド）で塗ると、視線を止めるべき要素（価格）と競合し、優先順位が分裂する。**強調はサブ色（バイオレット）で行い、アクセント色は価格のみに集中させる**。

---

### 5. 階層構造 — 情報の優先順位を視覚化する

すべての情報に優先順位をつけ、大きさ・色・太さで差をつけることで、何が最も重要かを一目で伝える。この「大きい要素と小さい要素の差」を**ジャンプ率**と呼ぶ。サムネイルではジャンプ率を**高く取る**（差を大きくする）ことが効果的。

**お手本（v2.0）での3段階の階層**

| 階層 | 要素 | 視覚的な処理 | 目的 |
|---|---|---|---|
| 第1階層 | 価格「4,000」 | 最大フォント・ゴールド | 一瞬で価格を伝える |
| 第1階層 | キャッチコピー | 大フォント・白＋バイオレット強調 | 一瞬で内容を伝える |
| 第2階層 | サブコピー | 小フォント・白＋縦線 | 補足情報で安心感 |
| 第3階層 | ラベル「DSL納品」 | バッジ・バイオレット背景 | カテゴリ即時認識 |

**ジャンプ率の実数値（v2.0）**
- 価格「4,000」= **211.2px**
- キャッチコピー = **119px**
- サブコピー = **43.2px**
- 比率 = **4.89 : 2.76 : 1**

v1.0 の比率（4.89:2.89:1）から微減（中段がやや小さく）したが、ジャンプの大原則は維持。

**全部同じ大きさにしてはいけない理由**
すべてのテキストを同じサイズで並べると、どれが重要かわからなくなる。ユーザーは一瞬でサムネイルを判断するため、「何を読めばいいか」が明確でないサムネイルはスルーされる。階層を設けることは、ユーザーに「まずここを見てください」というナビゲーションを提供すること。

## 5つの黄金律チェックリスト

サムネイル作成時は以下5項目を必ず確認。すべて満たしていればデザインの基礎として破綻しない。

| No. | 項目 | 確認ポイント |
|---|---|---|
| 1 | 構図 | 中央集約型で配置されているか？縦方向の優先順位は明確か？ |
| 2 | 配置 | 重要な要素が上寄りに配置されているか？下部に重要情報を置いていないか？ |
| 3 | 文字数 | キャッチコピーが15文字以内か？スマホ縮小表示で読めるか？ |
| 4 | 配色 | 3色（+白）以内か？70:25:5の比率に近いか？背景と文字のコントラストは十分か？アクセント色は価格1要素に集中しているか？ |
| 5 | 階層 | 第1〜第3階層の優先順位が明確か？ジャンプ率は211/119/43を維持しているか？ |

---

## 運用ルール

1. **ゼロから作るな。** お手本HTML（#26 v2.0）をコピーしてから編集する
2. **ジャンプ率を崩すな。** 211px / 119px / 43px の比率（4.89:2.76:1）は維持
3. **3色を超えるな。** ベース/サブ/アクセントの70:25:5を維持（白は独立扱い）
4. **明朝体を使うな。** 縮小で潰れる
5. **重要情報を下部に置くな。** プラットフォームのタイトル/価格と重なる
6. **アクセント色を分散させるな。** 価格のみに使用。強調文字はサブ色で
7. **マスター承認なくこのvest1を入れ替えるな。** 派生版がお手本を上回った場合は昇格プロセス（README.md参照）

## PNG書き出し（puppeteer）

参考実装: `products/dify-service/tmp/thumb-to-png.js`

```javascript
const puppeteer = require('puppeteer');
(async () => {
  const browser = await puppeteer.launch({ headless: true });
  const page = await browser.newPage();
  await page.setViewport({ width: 1260, height: 1280, deviceScaleFactor: 2 });
  await page.goto('file:///' + filePath.replace(/\\/g, '/'), { waitUntil: 'networkidle0' });
  await page.evaluate(() => document.fonts.ready);
  await new Promise(r => setTimeout(r, 1500));
  const el = await page.$('.thumbnail');
  await el.screenshot({ path: outPath, type: 'png' });
  await browser.close();
})();
```

`deviceScaleFactor: 2` で 2440×2480 相当の高精細PNGが得られる。
