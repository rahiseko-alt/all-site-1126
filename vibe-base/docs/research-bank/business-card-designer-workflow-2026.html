結論（最重要・So What）
プロは「コンテンツ先決め → 構造（グリッド） → 余白を構造内で配分 → 詳細」の順で作る。
日本では 「カード分解」という用語は登場しない。代わりに 「4原則（近接・整列・反復・コントラスト）」「3列グリッド」「ラフ3案 → 修正2回」が共通言語。
欧米では "Grid System" "Modular Grid"（Müller-Brockmann / Vignelli） が40年以上の業界標準で、本質的に「ブロックを格子に配置してから中身を詰める」=ユーザー提案と同義。
結論: 提案は名前こそ違うが、業界標準の「Modular Grid + 4原則」と本質一致。横型では強く機能、縦型では「ブロック分解」より「段分解＋中央軸」に読み替える必要あり。

ヒアリング項目（9項目・順序固定）

  1. 業種・職種・事業内容
  2. ターゲット（誰に渡すか）
  3. 名刺で達成したい目的（覚えてもらう / 信頼感 / 受注 / 紹介経由）
  4. 既存ブランド有無（ロゴ・CIカラー・既存名刺）
  5. 掲載情報の列挙（氏名・肩書・住所・TEL・メール・URL・QR・SNS）
  6. 印刷区分（片面/両面）・タイプ（縦×縦/縦×横/横×横）・サイズ
  7. 雰囲気の軸（シンプル⇔複雑 / 単色⇔カラフル / 暗⇔明 / 日常⇔高級 / 遊⇔厳粛 / 未来⇔伝統 / 女性的⇔男性的）
  8. 予算
  9. 納期
順序論の判定（複数ソース一致）:
国内主流は「コンテンツ先決め」。design-benkyo / 名刺スタイリスト / ricoh / fujiplus / canva / adobe.com の6社が「情報整理 → 優先順位付け → デザイン制作」と明示。
ただしサムネイル段階では「コンテンツと構造を同時に粗く決め、ラフでブロックが確定する2段階モデル」。

「カード分解」用語の登場有無

登場せず。代わりに以下が共通言語:

  • 近接・整列・反復・コントラスト（4原則・ricoh / fujiplus）— 関連項目を「塊化」する原理
  • 3列グリッド（hanjou・印刷名刺の標準）
  • 視線の流れ（横型=Z法則、縦型=N法則）

余白設計のタイミング（複数ソース一致）

「余白は構造定義（grid 設定）と同時に決まる積極的要素」で一致。

  • Smashing Magazine: 「white space was used as a dynamic component in layout design」
  • LinkedIn: 「Use a grid system ... in deciding where to allow for negative space」
  • Printing Peach: 「Proper alignment of elements can naturally create negative space」
  • Lupton (Thinking with Type): 「The grid creates the conditions under which spontaneity and expression become possible」

→ 「最後にバランス調整で空ける」のではなく、grid／module を切った瞬間に余白配分が確定する。

縦型の海外での扱い

  • 位置づけ: 「less conventional / more modern」「young, trendy brands or creative individuals」(Brandly Blog)
  • 業界例: salons / artists / photographers
  • 日本との関係: 「Japanese cards more commonly utilize both horizontal and vertical layouts to accommodate different writing systems」
    → 日本では文字体系（縦書き漢字）由来の必然、欧米では 選択的スタイル という非対称性
  • 設計注意: 「Keep your important details toward the center」（縦型は裁ち落とし事故が増えるため center-bias 推奨）

軸3. 縦型名刺特有の差分（「段分解＋中央軸」が正解）

横型 vs 縦型のフロー差分

工程横型縦型差分の本質
情報の流れ左→右（西洋型）上→下（日本型・看板型）視線軸90°回転
氏名配置中央〜左寄せ中央配置がほぼ定石縦軸の中心に「人物の名前」を据える儀礼性
文字組カーニング自由ベタ組み厳守＋行間広め縦組みは詰まりやすい（モリサワ）
数字算用数字漢数字 or 縦中横（2桁単位）DTP工数追加
英文そのまま自然縦書きと衝突 → 混在ルール必須混在処理が必要
ロゴ位置左上が主流右上が主流縦組みの起点と一致
余白の役割装飾的儀礼的（和の「間」）埋めずに残す

業界統計

横型 71% / 縦型 29%（グラフィック調べ）。縦型はマイノリティだが士業・伝統工芸・経営者・神職・和食店では多数派。

業種別の縦書き氏名配置傾向

業種定番配置備考
士業（弁護士・税理士・司法書士）中央＋両端揃え誠実・知的
茶道・華道中央＋大余白「間」重視
経営者中央＋最大級サイズ人物本位
神職中央＋明朝体＋市松柄名刺ファースト等に専用テンプレ
和食店屋号上＋店主名中央＋住所下3段構造
クリエイター右寄せ・自由配置個性表現

ふりがな（ルビ）配置ルール

  • 縦書きでは右側に配置（小林敏「ルビの配置方法」・上毎印刷）
  • 肩付き or 中付きを全体で統一（混在禁止）
  • 姓名はグループルビが多数（読み流しやすさ）
  • サイズ: 親文字の天地左右 1/2、面積 1/4 が基本
  • 名刺の慣行として親文字より薄いグレー or 細ウェイトにする例多（モリサワコラム）

縦書きに電話番号を載せる3択

  1. 漢数字（〇三・一二三四・五六七八）— 最格式
  2. 算用数字＋縦中横（2桁ごと回転）— DTP実務の主流
  3. 算用数字を縦に流す＋区切り記号統一 — モダン

縦型の数値定石（三栄印刷ほか）

  • ロゴ位置: 左角または右角 4〜6mm
  • フォントサイズ: 氏名 18pt / 会社名 12〜14pt / 肩書 6〜10pt / 住所 6pt
  • 段階配置: 「会社・部署 → 名前 → 住所」の先頭位置を順に下げる（斜め下流型）
「ブロック／カード分解」の縦型適合度
縦型ではブロック分解は機能限定的。「段分解」が正解。
  • 横並びブロック（左右に箱を並べる）= 縦軸を破壊するため禁忌
  • 縦並びブロック（上下に積層）= 機能する
  • 「右上=社 / 中央=名 / 左下=連絡」の 対角3点ブロック = 古典定石として機能
  • 均等9マスグリッド = 中央軸の儀礼性が消えるため非推奨
機能する条件: ①ブロックは縦積みのみ ②中央軸を貫く要素（氏名・ロゴ）はブロックから独立 ③対角3点配置を採用

統合分析 — マスター提案「カード配置」の業界位置と本件への適用

① 提案の正体（業界用語にマッピング）

マスター提案業界用語（海外）業界用語（国内）関係
カードで全体構成を決めて→中身を決めるModular Grid / Grid System / Compositional Grid3列グリッド + 4原則（近接・整列）本質一致（呼び名が違うだけ）
余白も含めて構造を先に決める"Grid creates conditions for spontaneity"（Lupton）「ラフでブロック確定 → 仕上げで mm 調整」業界40年の標準
今後の改修もカード単位でIdentity System / Brand System の1 application 設計テンプレ思想主流

② 提案の妥当性判定

横型・LP・印刷物全般 → 強く支持（業界標準）
Müller-Brockmann / Vignelli が確立した「構造ファースト」と完全一致。Vignelli は Knoll で名刺〜タグ〜箱を同一グリッドで設計した。
縦型名刺 → 条件付き支持
「ブロック分解」を縦型でやる場合、段分解＋中央軸に読み替えが必要。横並びブロックは縦軸を破壊する。
具体的には: ①積層ブロック ②氏名/ロゴは中央軸貫通要素として独立 ③対角3点配置（右上=社・中央=名・左下=連絡）を採用。

③ 本件名刺への適用方針

カード含むもの役割位置
①氏名カード縦書き氏名2字 + ふりがな中央軸貫通の主役要素上1/3〜中央
②肩書スロット肩書1行（マスター後入れ）氏名カードと連絡先カードの接続部top 62.4mm 付近・高さ3.9mm
③連絡先カードメール + 電話2行中央寄せtop 66〜70mm
④QRカードQR画像のみ下1/3の中央top 74.55mm

縦積み・中央軸・対角3点配置の 3条件すべて満たす 構造。提案は本件の縦型名刺で機能する。

④ 国内実務に合わせる場合の追加ポイント

  • 4原則の言語化: カード = 「近接・整列の塊化」と説明すれば国内実務者に伝わる
  • 3列グリッドの当てはめ: 横方向は 5mm / 45mm / 5mm の3列で全カードの左右余白を統一
  • ラフ3案文化: カード分解を採用しても「ラフは3案提示」の慣行は維持（クライアントに選んでもらう要素を残す）
  • 修正2回想定: カード単位で書けば修正局所化＝2回内に収まる構造が組める
