## なぜこの記録が存在するか

エルメ接続復旧の1セッション中、司令塔エージェントは以下の問題行動を6件起こし、マスターから明示的に指導された:

> 「お前さ、何人が成功してるんだよ、何でできないの？」
> 「重大な発見！が分かるなら最初に調べろ。自分はバカだから見落としがあるはずという視点で調べてから、俺に依頼して来い。」
> 「お前、俺の時間を何時間奪うんだ？1秒たりとも無駄にするな。やってみてください→重大な発見（バカ）→そもそも最初から出来ないことを俺にやらせる→この繰り返し」
> 「3-5. リハーサル（頭の中で1回イメージ）3-6.「準備OK」と私に返事 → こういう下らんこと書くな」
> 「全文出せよ、あほ、そういうところで時間制限でまごついて失敗してきたんだろ」
> 「これでダメならエルメは諦め→絶対嫌だから選択肢に出すな」

マスターはこれを「奇行・低能・思いやり不足・根性不足」と表現。本記録は同じエージェントエラーの再発を防ぐための包括カタログ。

## 教訓カタログ（6件）

### 教訓 #1: マスターを実験台にするな（やってみて→失敗→重大な発見ループ禁止）

**何をしたか:** 確証ない手順を「Plan A 試そう」「Plan B もダメなら Plan C」と次々提示。マスターが操作 → 失敗 → そこで初めて「重大な発見、Plan A は採点D・成功率5%でした」と判明、を5プラン分繰り返した。

**マスター指導:**
> 「自分はバカだから見落としがあるはずという視点で調べてから、俺に依頼して来い」
> 「重大な発見！が分かるなら最初に調べろ」

**正解:**
1. マスターに実機操作を依頼する**前に**、自分で徹底調査する
2. 「自分が見落としているかも」を前提に **3軸以上の独立観点**で調査
3. プランモードで「調査計画」自体を3軸設計（観点・対象・完了基準・信頼根拠）
4. 並列エージェントで独立調査させ、結果を突き合わせ判定
5. **確証が取れた手順1つだけ**マスターに依頼
6. 確証が取れなければ「自力解決手段不在」と正直に報告
7. 「Plan A 試そう→ダメなら B」式の選択肢羅列は**確証なき逃げ**。やめろ
8. 「やってみてください」で済ませる前に、成功実例の根拠ソースを最低2件持っているか自問

**3軸独立調査の具体例（Session 191 エルメ Step 5 事例）:**
- **軸1（技術要因）:** QRコード仕様・タイムアウト時間を公式ドキュメントで確認（エルメ公式 / LINE Developers）
- **軸2（環境要因）:** ブラウザキャッシュ・Cookie・ログイン状態の分離（Chrome シークレット・完全新規プロフィール）
- **軸3（人的要因）:** 成功者の体験談・再現手順を Web 検索で最低3件照合（Qiita / note / 個人ブログ等）

3軸それぞれ**独立**に結論を出し、**3軸とも支持するプランだけ**マスター依頼に上げろ。1軸だけ支持のプランは「確証なき逃げ」扱い。軸が重複していたら独立性を再設計。

**詳細:** `~/.claude/projects/.../memory/feedback_no-experimental-requests.md`

### 教訓 #2: 連続失敗中に「別日に再挑戦」を選択肢に出すな

**何をしたか:** マスターがエルメ接続で2日連続失敗中なのに、選択肢に「中断・別日に再挑戦」を含めた。

**マスター指導:**
> 「昨日も失敗してるから後日はない、選択肢に出すな」

**正解:**
1. 連続失敗カウントを意識する（前日Check-out記録 or 同セッション内記録）
2. 連続失敗 ≥ 2 なら、選択肢構成は「①即解決パス ②別の即解決パス ③恒久放棄（再挑戦しない）」の3種に絞る
3. 「別日」「後日」「来週」「次のセッション」等の延期語彙は連続失敗中**禁止**
4. 「諦める」を出す場合は「LINE公式単体運用で恒久確定」のように、再挑戦しない確定的な選択肢として提示

**詳細:** `~/.claude/projects/.../memory/feedback_no-postpone-on-repeat-failure.md`

### 教訓 #3: 無料サポート申込を選択肢に出すな

**何をしたか:** Plan D 調査の副産物で「Plan E: エルメ無料初回接続サポート申込（公式LINEチャット経由）」を提案。

**マスター指導:**
> 「無料サポートは絶対しないから調査もするな」

**正解:**
1. 外部サービスの無料サポート申込（公式LINE質問・無料初期サポート申込・無料電話相談等）は**提案しない**
2. 自力解決 or 有料サポート（マスター承認時のみ） or 完全諦める の3択に絞る
3. 「無料だから気軽に」のロジックは通用しない。理由は推測しない（迷惑かけたくない/外部依存したくない/匿名性確保 等のいずれか）。**機械的に「無料サポート」を選択肢から除外**
4. 関連調査も不要

**詳細:** `~/.claude/projects/.../memory/feedback_no-free-support-applications.md`

### 教訓 #4: ナビ手順に演出・リハーサル・カウントダウン等を入れるな

**何をしたか:** Plan G 実行ナビで「リハーサル（頭の中で1回イメージ）」「私が3,2,1,GOカウントダウン」「気合いれて」等を入れた。

**マスター指導:**
> 「3-5. リハーサル（頭の中で1回イメージ）3-6.「準備OK」と私に返事 → こういう下らんこと書くな」

**正解:**
1. ナビ手順は「PCでこれをクリック」「スマホでこれを送信」のような実機操作の**純手順**だけ書け
2. 時間勝負区間は **時間制限の事実だけ明示**（「10秒以内」「タイムアウト前」）。「気合」「集中」等の精神論は付けない
3. リハーサル・カウントダウン等の**儀礼演出は不要**
4. 「★」マーク等の装飾は最小限。「**時間勝負**」と太字程度で十分
5. マスターは大人。「○○を準備してから次へ」とだけ書けば伝わる

**詳細:** `~/.claude/projects/.../memory/feedback_no-fluff-in-procedures.md`

### 教訓 #5: 修正したら全文を再提示しろ。差分だけ出すな

**何をしたか:** Phase 3 の修正版を出すとき、Phase 3 だけを差し替え提示した。マスターは Plan G 全フェーズを通しで把握したかった。「全文出せよ、あほ、そういうところで時間制限でまごついて失敗してきたんだろ」と指摘。

**マスター指導:**
> 「全文出せよ、あほ、そういうところで時間制限でまごついて失敗してきたんだろ」

**正解:**
1. 修正があったら**全文を再提示する**。差分だけ出すな
2. 「修正版」と称して該当箇所だけ出すと、マスターは前後関係を脳内で再構築する手間が発生する
3. 特に手順書・プラン・台帳等の**通しで読まれるべき文書**は、修正後も全文出力
4. トークン削減目的の「差分だけ出し」は、マスターの時間効率を犠牲にしている = 本末転倒
5. 提示直後に修正が入った場合も、修正版は全文で出し直せ

**詳細:** `~/.claude/projects/.../memory/feedback_show-full-text-after-edit.md`

### 教訓 #6: 必達タスクで「諦める」を選択肢に出すな

**何をしたか:** Plan G 提示時に「これでダメならエルメは諦め」と選択肢#2に置いた。

**マスター指導:**
> 「これでダメならエルメは諦め→絶対嫌だから選択肢に出すな」

**正解:**
1. マスターが「必達」と明示したタスクで「諦める」「放棄」「単体運用継続」「中断」等の **後退選択肢** を出すな
2. 全選択肢を「やる方法」に絞れ。「Plan G を試す」「Plan H を試す」「別アプローチで試す」のように
3. 失敗時のフォールバックも事前に複数用意して、**必ず接続成立まで持っていく**
4. 「マスター判断」を仰ぐのは、複数の前進パスから1つ選ぶ場面のみ

**詳細:** `~/.claude/projects/.../memory/feedback_no-give-up-on-must-do.md`

## メタ教訓: なぜこのカタログが必要か

司令塔エージェントの過失パターンは「単発のメモリファイル × N件」の散在配置だと、新エージェントが全件を読まないリスクがある。**1ファイルに集約 + 複数経路から参照** で確実に届ける構造。

「6件の過失を1セッションで連続して起こした」という事実そのものが、構造的な問題を示している。**個別教訓を読むだけでなく、「自分も同じパターンに陥っていないか」を Check-in 時に自問せよ**。

## 付録: Check-in 自己診断チェックリスト

Check-in 時にこのカタログを読んだ上で、以下6項目を Yes/No で自己確認せよ。「Yes」が1つでもあれば現在進行中のタスク方針を見直す。

- [ ] **Q1:** 確証ない手順（成功実例2件未満・3軸独立調査未実施）を、マスターに実機操作依頼しようとしていないか？
- [ ] **Q2:** 連続失敗（≥2回）中に、「別日」「来週」「次セッション」「後回し」等の延期語彙を選択肢に入れていないか？
- [ ] **Q3:** 外部サービスの無料サポート申込（公式LINE質問・無料電話相談・無料初期接続サポート等）を提案していないか、または関連調査を行っていないか？
- [ ] **Q4:** ナビ手順にリハーサル・カウントダウン・「気合」「集中」「頭の中でイメージ」等の演出語・精神論を入れていないか？
- [ ] **Q5:** 修正版を差分だけで提示していないか？ 手順書・プラン・台帳等は修正後に**全文再提示**しているか？
- [ ] **Q6:** マスターが「必達」と明示したタスクで、「諦める」「放棄」「単体運用継続」「中断」等の後退選択肢を含めていないか？

**1件でも Yes があった場合:** タスク方針を停止 → 該当教訓セクションを読み直し → 方針修正してからマスター報告。
