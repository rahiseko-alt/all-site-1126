### 重要な学び

- **「過ぎたるは及ばざるが如し」を Plan Mode でも発動させる**（Session 225 教訓の継続）。事前調査エージェントの報告を鵜呑みにせず Glob で実体照合する規律違反を即発覚 → memory に保存して次セッション以降のガード化

- **自己検証スクリプト自身が K5 違反になる構造的不備**: スクリプトのメッセージ内文字列が検出対象になる再帰的誤検知 → 「メッセージ内の旧パス文字列」と「動作するコードでの旧パス参照」の区別を明示。次回類似パターン（自己言及コードチェック）の参考事例
- **Phase D 並列エージェント委任は規模圧縮に有効だが品質バラつきリスクあり**: 3 体で 12 プロダクト × 1-3 ファイル = 約 30 ファイルを 90 分で完遂。ただし risk-diagnosis 不在対応の判断が割れた（D1=スキップ / D2=スキップ / D3=新規作成）→ 委任 prompt の規律強化が課題
- **K3「計画書 ≠ 現状」は Plan Mode 内でも再発する**: Plan Mode の本来目的は「自分で調べる」だが、エージェント報告依存で照合をサボると即発覚する。「Plan Mode の Explore は徹底調査が必要」を memory 化
