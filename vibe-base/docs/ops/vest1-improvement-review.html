#10-11 障害シナリオ分析テンプレート

これは何か（素人向け）

「壊れたらどうなる？」を事前に全部洗い出すチェックシートの雛形。
ソフトウェアは色々な理由で壊れる。ネットが切れる、サーバーが落ちる、無料枠を使い切る、パスワードが消える…。
この雛形を使うと「壊れるパターン」「お客さんへの影響」「今の対策」「追加で必要な対策」を表にして漏れなく整理できる。
例: ビルの防災計画。「火事が起きたら？」「停電したら？」「水が止まったら？」を全パターン書き出して、それぞれ対策を決めておくのと同じ。

#12 外部サービス確認テンプレート

これは何か（素人向け）

「うちの製品が依存している外部サービス」の健康診断表の雛形。
うちの製品はGoogleのAI、Stripeの決済、Vercelのサーバーなど、他社のサービスに乗っかって動いている。
それぞれの「無料でどこまで使えるか」「上限を超えたらどうなるか」「最近仕様変更はあったか」を一覧にして管理する。
これをやらないと、ある日突然「無料枠使い切りました、サービス止まりました」が起きる。
例: 飲食店が「ガス会社」「電力会社」「食材卸」のそれぞれについて、契約内容・料金プラン・緊急連絡先・過去のトラブル履歴をまとめた一覧表を持っているようなもの。

#13 テスト計画テンプレート

これは何か（素人向け）

「この操作をしたら、こうなるはず」を全部書き出して、1つずつ確認するチェックシートの雛形。
ソフトウェアのテストは「ログインボタンを押したらログインできる」「不正な入力をしたらエラーが出る」のような項目を何十個も並べて、1つずつ手で確かめる作業。
この雛形があれば、テスト項目の分類（認証/コア機能/エラー処理など7グループ）が決まっているので、抜け漏れなくテストできる。
例: 車の出荷前検査シート。「エンジンかかるか」「ブレーキ効くか」「ライト点くか」を項目ごとに○×つけていくのと同じ。

5W2H

What手動テストケースの計画書。7グループ（認証/ユーザー管理/コア機能/データ操作/外部連携/エラー/レスポンシブ）に分類して網羅的にテストする
Why「動くはず」を「動いた」に変える。テストせずにリリースすると、お客さんの前でバグが出る
Whoエージェントがテスト項目を記入+実行 → 結果を記録 → マスターに報告
WhenP1（開発フェーズ）の#10-11タスク「手動テスト・レスポンシブ確認」
Wherevest1: docs/ops/test-template-guide.md → 各プロダクトの docs/test-plan.md にコピー
How7グループのテンプレをコピー → 自分のプロダクトの機能に合わせてテスト項目を記入 → 1件ずつ実行して結果を記録
How muchテスト項目作成: 1時間。テスト実行: 機能数×10分程度

検出された改善点:
vest1の4列テーブルには「結果」列がない。テストは「項目を書く」→「実行する」→「結果を記録する」の3段階なのに、雛形が「結果を記録する」欄を用意していなかった。

改善案: 4列 → 5列に拡張
| # | テスト項目 | 手順 | 期待結果 | 結果 |

車検シートに例えると: 「ブレーキ」「踏む」「止まる」の3列だけで、「OK/NG」を書く欄がなかったのを追加するだけの話。
vest1に「結果」列を追加 4列→5列の軽微な改善。テスト実行後に○×を記録する欄が必要
