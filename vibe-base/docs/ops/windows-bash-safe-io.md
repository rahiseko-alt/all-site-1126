# Windows 環境での Bash 安全 I/O 手順（E-7・2026-07-10 策定）

> **前提**: 本文書は回避策の集約であり根治ではない。Bash ツールの内部実装（heredoc パーサ・エスケープ処理）は Claude Code 側の実装に依存し、vibe-base 側から制御不能なため、根治ではなく運用回避策止まりである。

## 1. 多行文字列の保存

Bash の heredoc に多行文字列（特に日本語混じり・引用符混在）を直接通すと、エスケープ崩れや文字化けが起きやすい。

- **正しい手順**: `Write` ツールで一時ファイル（scratchpad 配下）に書く → `cp` でバイト正確にコピーする。
- heredoc を使う場合も、複雑な内容（JSON・多言語混在・特殊文字）は避け、単純なテキストに限定する。

## 2. git commit の多行メッセージ

`git commit -m` に多行メッセージを渡す際、PowerShell here-string 記法（`@'...'@`）を Bash の heredoc（`<<'EOF'...EOF`）と混同して混ぜない。

- **実例（2026-06-06）**: 記法の混在により commit subject が文字化けした。
- Bash ツール内で完結させる場合は `git commit -m "$(cat <<'EOF' ... EOF)"` の形に統一し、PowerShell 記法を持ち込まない。

## 3. Windows パスの操作

Windows パスの `\` を `sed` で置換しない。

- **実例（2026-06-19）**: `sed` によるパス区切り文字置換が空振りした。
- パス操作（区切り文字変換・結合・正規化）は `node` の `path` モジュールを使う。
