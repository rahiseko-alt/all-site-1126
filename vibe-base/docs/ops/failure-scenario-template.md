## 目的

プロダクトの全障害パスを事前に洗い出し、ユーザー影響と対応策を記録する。「壊れたらどうなるか」を網羅的に検証し、致命的な障害を放置しない。

---

## 分析テーブルのフォーマット

各カテゴリについて以下の表を作成する。

```markdown
## {カテゴリ名}

| # | シナリオ | 発生条件 | ユーザー影響 | 現行対応 | 追加対応 |
|---|---------|---------|-------------|---------|---------|
| {カテゴリ}-1 | {何が起きるか} | {いつ・どう起きるか} | {ユーザーに何が見えるか} | {今の実装で何が起きるか} | {必要な追加対応 or "問題なし"} |
```

## 7カテゴリ（必須チェック項目）

### 1. 認証・セッション系

| チェック項目 | 典型シナリオ |
|-------------|-------------|
| セッション/JWT期限切れ | 長時間放置後の操作 |
| 認証用環境変数の未設定 | デプロイ時の設定漏れ → 起動不可 |
| OAuthトークン失効 | ユーザーが外部サービス側で権限取消 |
| refresh_token未取得 | 初回OAuth時のprompt設定ミス |

### 2. DB系

| チェック項目 | 典型シナリオ |
|-------------|-------------|
| 接続タイムアウト | DBサーバー障害 / コールドスタート |
| 無料枠超過 | コンピュート時間 / ストレージ超過 → 接続拒否 |
| スキーマ不整合 | マイグレーション漏れ → 実行時エラー |
| 同時書込み競合 | 複数タブ/ユーザーの同時操作 |

### 3. 外部API系（サービスごとに作成）

| チェック項目 | 典型シナリオ |
|-------------|-------------|
| APIキー未設定 | 環境変数漏れ → 機能停止 or 起動不可 |
| クォータ超過 | 429エラー → 一時的な機能停止 |
| API未有効化 | 403エラー → 「有効化してください」 |
| タイムアウト | ネットワーク遅延 → AbortControllerで制御 |
| ページネーション異常 | 無限ループ → 最大ページ数でbreak |

### 4. AI/LLM系

| チェック項目 | 典型シナリオ |
|-------------|-------------|
| APIキー未設定 | 環境変数漏れ。top-level throwは避ける（遅延初期化推奨） |
| タイムアウト | モデル過負荷 → タイムアウト制御 |
| 不正レスポンス | JSONパース失敗 → フォールバック値 |
| クォータ超過 | 無料枠超過 → エラーメッセージ表示 |

### 5. ホスティング系（Vercel等）

| チェック項目 | 典型シナリオ |
|-------------|-------------|
| 関数タイムアウト | Hobby=10秒制限。重い処理で502 |
| ビルド失敗 | 型エラー/依存関係 → デプロイ不可（既存版は継続） |
| 環境変数未設定 | 該当機能停止 |

### 6. ネットワーク・ブラウザ系

| チェック項目 | 典型シナリオ |
|-------------|-------------|
| オフライン | fetch全失敗 → エラー表示 |
| CSRFトークン不一致 | タブ長時間放置 → POST失敗 |

### 7. データ整合性

| チェック項目 | 典型シナリオ |
|-------------|-------------|
| 重複データ作成 | ユニーク制約の欠如 |
| カスケード削除の影響 | 親レコード削除時の子レコード挙動 |
| 楽観的ロックの失敗 | 同時更新による上書き |

## 優先度判定基準

分析完了後、追加対応が必要な項目を優先度で分類する。

| 優先度 | 基準 | 対応タイミング |
|--------|------|-------------|
| **高** | アプリ起動不可 / データ消失 / セキュリティ脆弱性 | P1スコープ内で即対応 |
| 中 | 特定機能の停止（回避策あり） | P1内で対応推奨、P2でも可 |
| 低 | UX劣化（機能は動く） | P2以降 |

---

## プロダクト側の使い方

1. 本テンプレートをコピーして `products/{product}/docs/cl3-failure-scenarios.md` を作成
2. プロダクトが使う外部サービスごとにカテゴリ3のテーブルを作成
3. 全7カテゴリを埋める（該当しないカテゴリは「該当なし」と明記）
4. 優先度判定を行い、高優先度はP1タスクに追加
