# ログ・監視設計テンプレート

### これは何か

「壊れたとき、どうやって気づくか」の設計書。エラーログの保存先・アラートの発火条件・死活監視の方法を決める。これがないと障害が起きても誰も気づかない。

### 5W2H

| 項目 | 内容 |
|------|------|
| **What** | 本番稼働後のログ収集+エラー通知+死活監視の設計テンプレート |
| **Why** | 障害発生時に「いつ・何が・なぜ壊れたか」を即座に特定するため。設計なしだとログがバラバラで原因究明に時間がかかる |
| **Who** | エージェントが設計・記入 → マスターが確認 |
| **When** | ログ・監視設計時 |
| **Where** | vest1: docs/standards/templates/monitoring-design.md → 各プロダクトの docs/ にコピー |
| **How** | コア機能+外部API連携ごとにログポイント・アラート・監視を設計 → 表に記入 |
| **How much** | 設計30分。実装は別途 |

### 現時点の実装手段

| 方法 | コスト | 導入難度 | 備考 |
|------|--------|---------|------|
| Vercelログ（手動確認） | 無料 | なし | Hobby: 1時間分のみ保持 |
| Sentry（エラー監視） | 無料枠あり | 低 | 月5,000イベントまで無料 |
| UptimeRobot（死活監視） | 無料 | 低 | 5分間隔。50モニターまで |
| Resend + cron（定期レポート） | 無料枠内 | 中 | 日次でエラー件数をメール |

## 4. 障害時の対応フロー

```
1. アラート受信
2. Vercelログで直近エラーを確認
3. 外部API側のステータスページを確認
4. 原因特定 → 修正 → デプロイ
5. memory.mdに障害記録
```
