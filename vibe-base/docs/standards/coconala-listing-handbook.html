§1. 市場調査 構成骨格 + 調査手順

新規出品カテゴリを調査するとき、調査レポートに含める 7ブロック と、そのブロックを埋めるための 調査手順 を両方規定する。手順に従えば、どのモデルでも同じ粒度の成果物になる。

1-1. レポートに含める7ブロック

#ブロック含めるべき情報
1カテゴリ概要カテゴリ名 / 親カテゴリ / ID / 総出品数 / カテゴリ累計実績 / サブカテゴリ一覧
2上位20件一覧（ランキング順）タイトル / キャッチコピー / 価格 / レビュー数 / 星評価 / 本文記載の販売実績 / ランク
3価格帯分布中央値・最頻値・上限下限（平均値のみは禁止）/ ヒストグラム / サンプル件数明記
4訴求パターン分類問題提示型 / ROI訴求型 / 技術ロゴ型 / 納品物列挙型 / 価格訴求型 の各割合
5空白地帯の特定他社が埋めていない切り口。例: ROI数値訴求の空白、特定業種特化の空白
6サムネ構成分析要素数（3要素以下の割合）/ 技術ロゴ使用率 / 星評価表示率 / PRバッジ有無
7総評・空白地帯推奨参入するならどの切り口が有利か / 撤退すべきか / 価格戦略（追随/差別化/空白）

1-2. 調査手順（ブロック1〜7の埋め方）

  1. ステップ1: 対象カテゴリの公式ページを WebFetch で取得する。URL は https://coconala.com/categories/{id}?sort_by=ranking。HTML 全体を取得してカテゴリ名・総出品数・サブカテゴリをブロック1に記録。
  2. ステップ2: 同ページから上位20件のサービス行を抽出。各行について「タイトル / キャッチ / 価格 / レビュー数 / 星評価 / 出品者ランク」を取得しブロック2に表形式で記録。本文記載の販売実績は必ず個別ページを開いて本文から採録せよ（カード上には非表示のため）。
  3. ステップ3: ブロック2で取得した上位20件の価格列を数値で並べ、中央値・最頻値・最小・最大を算出しブロック3に記載。「平均値のみ」は禁止。サンプル件数を必ず併記。
  4. ステップ4: 上位20件のタイトルとキャッチコピーを読み、以下の5類型のどれに当てはまるかラベル付けしブロック4に割合で記載: 問題提示型（質問形式）/ ROI訴求型（数値削減強調）/ 技術ロゴ型（ツール名羅列）/ 納品物列挙型（何が届くか箇条書き）/ 価格訴求型（相場より安い主張）。
  5. ステップ5: ブロック4で 割合10%未満の類型 を「空白地帯」としてブロック5に記載。空白の理由（需要なしか、誰もやっていないだけか）も推測で書け。
  6. ステップ6: 上位20件のサムネ画像を Playwright でスクリーンショット or WebFetch で取得し、以下を集計しブロック6に記載: 要素数（文字・ロゴ・アイコン・星評価・PRバッジの個別カウント）/ 3要素以下の割合 / 技術ロゴ使用率 / 星評価表示率。
  7. ステップ7: ブロック1〜6 の結果を踏まえて以下3問に答えブロック7に記載:
    • 参入するならどの切り口が有利か（空白地帯 / 上位追随 / 下位差別化）
    • 撤退すべきか（No-Go判定の根拠）
    • 推奨価格帯（中央値のN倍 or 最頻値同額 の根拠付き）
収集ツールの使い分け:
  • WebFetch — 上位20-80件の軽量収集（カード情報のみ）。最速。
  • Playwright MCP — サムネ画像・本文スクショ・動的レンダリングが必要な場合
  • 調査は長時間になりがちのため Agent + run_in_background: true 委譲を原則とする（CLAUDE.md §4.1）
データ粒度の絶対規律: 価格は 中央値・最頻値の実数を必ず出すこと。「相場はこれくらい」という曖昧な報告は禁止。サンプル件数を必ず明記する。
× 「相場は1万円前後」　→　○ 「中央値 12,500円（40件サンプル）/ 最頻値 10,000円（11件）」

1-3. ABC分析アルゴリズム + ハイブリッド参入戦略

市場調査の次のステップ。取得した80件データから ABC分析 を実行し、参入戦略を決める。

ABC分類アルゴリズム（評価数ベース）

  1. ステップ1: 80件のカードデータから 評価数（レビュー件数）を抽出（ココナラの「実販売数」はカード上に非表示で取得困難。評価数は実販売数の下限で、相対順位はほぼ同じ）
  2. ステップ2: 評価数ゼロの出品は除外（「販売数ゼロは統計から除外」規約）
  3. ステップ3: 残りを評価数降順でソート
  4. ステップ4: 累計評価数の割合を計算（累計% = 上から N 件までの合計 ÷ 全合計 × 100）
  5. ステップ5: 累計% で分類:
    • A群: 累計 0 - 80%（市場の寡占層）
    • B群: 累計 80 - 95%
    • C群: 累計 95 - 100%
  6. ステップ6: A群の価格分布を集計（中央値・最頻帯・価格ビン 5,000円刻み）
  7. ステップ7: 空白地帯を特定。A群の価格帯で件数が少ない帯（例: A群14件中 ¥4,000-¥9,000 帯が3件のみ = 空白地帯）
SSoT への書き込み先: monetization.xlsx の abc-analysis シートにサマリ1行追加（カテゴリ / 取得日 / A群件数 / 占有率 / 中央値 / 空白地帯 等）。raw data 80件は `journal/monetization/drafts/abc-cat{ID}-YYYY-MM-DD.xlsx` に個別インスタンスとして保管。全エージェントはセッション開始時に monetization.xlsx の catalog / abc-analysis / strategy シートを読むこと。
旧ツール参照: docs/standards/templates/abc-analysis-template.xlsx（5シート版）は初期検討時の VEST。現在は monetization.xlsx に統合されているため、新規分析時は monetization.xlsx を優先使用せよ。

ハイブリッド参入戦略（Session 169 確定）

原則（Session 169 訂正版）: Phase 1 の新規参入は以下 2択のみ:
  1. Route 1: 同価格で圧倒的に機能が上（A群中央値と同じ価格で、業種特化/納期保証/画面共有/返金保証/ヒアリング型等の差別化軸で勝つ）
  2. Route 2: 同機能で圧倒的に安い（A群と同等の機能を価格破壊で提供）
空白地帯で高単価独占は Phase 3 の「成長後戦略」である。Phase 1 で空白地帯高単価を狙うのは誤り。新規はレビュー0件から始まるため、A群と直接比較される価格帯で勝負するしかない。
Phase期間戦術目標
Phase 1
Route1 or Route2		 0-3ヶ月 A群同価格帯で Route 1（機能上）or Route 2（同機能で安く）で参入。差別化軸必須（業種特化 / 納期保証 / 画面共有サポート / 返金保証 / ヒアリング型カスタム開発 / 「ます抜き」キャッチ） レビュー 20件以上
Phase 2
A群展開		 3-6ヶ月 Phase 1 で蓄積したレビュー実績を武器に、A群内でのポジション確立（別価格帯サブ出品 or オプション拡充） A群入り
Phase 3
ブランド化		 6ヶ月+ A群特殊ポジション獲得。業種特化深化 / 技術特化深化 / 空白地帯高単価独占（ここで初めて成長後戦略として有効） 特殊ポジション確立

採用しない戦略（理由付き）

  • ❌ 空白地帯で高単価独占（Phase 1 で狙う）: レビュー0件の新規が空白地帯に入っても客が来ない。これは成長後（Phase 3）の戦略
  • ❌ A群完全真似（価格も文章もそのまま）: A群のレビュー169-992件の複利効果の壁を差別化軸なしでは超えられない

差別化軸の候補（Phase 1 で必須1つ以上）

  • 業種特化: 医療事務 / 美容室 / 保育園 / 建設業 / 士業 / 不動産 / 宿泊業 等
  • 納期保証: 48時間納品 / 24時間以内返信
  • 画面共有サポート: Zoom 等で一緒にセットアップ（有料オプション）
  • 返金保証: 動作不良時の条件付き返金
  • ヒアリング型カスタム開発: 購入後に業務をヒアリングしてからカスタマイズ納品（業務効率化部門の既定モデル）
  • 「ます抜き」キャッチの差別化: タイトルの語感差別化（ココナラは「〜ます」自動付与、§3-1 参照）
AIカテゴリ別に再分析必須: カテゴリごとに ABC分析 結果（寡占度・空白地帯・価格分布）は異なる。他カテゴリの結論（例: カテゴリ230）を別カテゴリ（例: カテゴリ22 Web制作 / 231 プログラミング）にそのまま適用するな。毎回 80件取得 → ABC分析 → 空白地帯特定 を実施せよ。

§2. 景品表示法 チェックリスト + 照合手順

なぜ厳格か: ココナラは出品時に景品表示法準拠の審査を実施する。違反があると出品停止・アカウント制限のリスク。グレーもアウト。1つでも該当したら即修正。

2-1. 絶対NG表現（即アウト）

パターン具体例
断定的効果保証「元が取れます」「稼げます」「必ず〜」「絶対〜」「確実に〜」
収益・黒字の断定「〇〇円の黒字が出ます」「購入初月から元が取れます」「高収入」
断定的削減表現「〇時間が消えます」「〇〇を撲滅」「手作業を排除」
根拠なし最上級「No.1」「最速」「最短」「ココナラで一番」「これ以上ない」
永続効果の断定「一生モノ」「永久に続く」「半永久的に」
成功率100%系「失敗した例はありません」「全員〜できています」「成功率100%」
根拠なし限定「期間限定価格」「〇件売れたら値上げ」（期間・条件の明示なし）

NG NGOK言い換え OK

「元が取れます」「元が取れる計算になります（〇時間削減の場合）」

2-3. ROI数値を使うときのOK形式

数値は出してよい。断定しなければよい。

  • OK 「月10時間削減の場合、最低賃金換算で月¥11,600分の節約試算になります」
  • OK 「試算：月〇時間 × ¥1,160（2026年度最低賃金）= 月¥〇〇の削減効果」
  • OK 「ご利用状況によって効果は異なります」の免責一文を必ず添える

2-4. 照合手順（文章完成後に必ず実行）

  1. ステップ1: 書き終わった出品文・タイトル・キャッチ・オプション説明・FAQ・注意事項 を 全文コピーし、1つのテキストにまとめる。
  2. ステップ2: 2-1 の NGパターン7種類それぞれについて、全文を検索する（Ctrl+F 相当）。1つでもヒットしたら該当箇所を即修正。ヒットがゼロになるまで繰り返す。
  3. ステップ3: 2-2 のグレー6パターンそれぞれについて、同様に全文検索。ヒットしたら 2-2 のOK言い換えに置換。
  4. ステップ4: ROI数値を含む文章があれば、2-3 の OK形式（「試算」「見込めます」「参考値」「ご利用状況によって異なります」の4要素）がすべて含まれているか確認。1つでも欠けたら追加。
  5. ステップ5: ここまでで問題なしを確認したら、文章末尾または注意事項内に 「景品表示法チェック済み（YYYY-MM-DD）」 の明示記載を1行入れる。これで完了。
セルフチェックでは不十分な場合: 新しい訴求パターンを使ったとき（例: 「返金保証」「〇日間無料」等）、本ハンドブックの NGパターンに未記載でも景品表示法違反の可能性がある。マスターに判断を仰げ。

§3. 出品文章 8ステップ + 執筆手順

カテゴリ230（業務自動化・効率化支援）の競合上位から抽出した、販売数上位に共通する文章構成。次の出品を書くときはこの順序で組み立てる。

3-1. タイトル・キャッチコピーの文字数仕様（重要・勘違い注意）

ココナラ独自仕様: タイトルは語尾に自動で「ます」が付与される。
つまり、マスターが入力する時点では「ます」を含めないで入力する。管理画面上で表示・カウントされる文字数は「ます」抜きでの文字数。

具体例

入力値（管理画面）ページ表示文字数カウント
ExcelマクロVBAで作業を自動化しExcelマクロVBAで作業を自動化します「ます」抜きで数える
WebサイトのデータをCSVに自動収集しWebサイトのデータをCSVに自動収集します「ます」抜き
面倒なPC作業をRPAで自動化し面倒なPC作業をRPAで自動化します「ます」抜き
やりがちなミス: 文章内で「〇〇します」とタイトル全体を書くと、ココナラが追加で「ます」を付けて「〇〇しますます」になる。必ず 「ます」抜きで入力 せよ。指定文字数（25字上限など）も「ます」抜きで計算せよ。

3-2. 文章構成 8ステップ

① 問題提示 → ② 共感 → ③ 解決策提示 → ④ 納品物の具体説明 → ⑤ ROI試算 → ⑥ 購入後ヒアリング → ⑦ FAQ → ⑧ 購入時お願い（注意事項）

3-3. 執筆手順（各ステップの書き方）

  1. ステップ①問題提示: 質問形式で1行。次に 箇条書き5項目 で「こんな業務していませんか？」を列挙。各項目は具体的な業務シーンを1行で書く（抽象論禁止）。
    「毎日同じExcel作業、いつやめられますか？」
    ・Excelで毎日コピペ・貼り付けを繰り返している
    ・帳票を1件ずつ手作りして残業が増えている
    ・リストの重複や表記ゆれを目視でチェックし続けている
  2. ステップ②共感: 1段落2-3文。読み手の挫折経験に寄り添う。「〇〇は難しそう」「何ヶ月も止まっている」等のフレーズを使う。
    「こうした繰り返し作業は、一度だけ正しく仕組みを作れば動かせます。自動化にかかるスキルも時間もなくて構いません。」
  3. ステップ③解決策提示: 「何を提供するか」を1段落で宣言。技術ハードルを下げる言葉（「〇〇不要」「ダブルクリックだけ」「コード1行も書かない」）を必ず入れる。
    「すぐに動く .bas ファイル（VBAコード）5本 + 自動インストーラーのセットをお届けします。Excelを開いてインストーラーを実行するだけで、その日から使えます。」
  4. ステップ④納品物の具体説明: ①②③④⑤の番号付きで、何が届くか具体的に列挙。各項目は「機能名 — 動作説明」の形式。動作環境（OS・Excel版・対応範囲）も最後に明示。
    「① データクリーニング — 空白行削除・全角→半角変換・会社名統一を一括実行 / ② シート間転記 — ...」
  5. ステップ⑤ROI試算: 景品表示法 §2-3 の OK形式を厳守。
    • 「月〇時間削減の場合」の前提を書く
    • 「最低賃金換算（時給約1,160円、2026年度）」の根拠を書く
    • 「月¥〇〇分の節約試算」と書く（断定しない）
    • 「※実際の削減効果はご利用状況・業務内容によって異なります」の免責を書く
  6. ステップ⑥購入後ヒアリング: 「購入後のメッセージにて以下をお知らせください」+ 質問3-5項目。納品の調整余地を示す。
    「1. 主に使いたい機能（①〜⑤） / 2. ExcelのバージョンとOS / 3. カスタマイズしたい処理の概要」
  7. ステップ⑦FAQ: 購入前の不安を 3-5問 で解消。必須テーマ: 環境依存（Mac対応・OS版）/ カスタマイズ可否 / 返金条件 / 技術要件（Python不要等）。
    「Q. 既存のExcelファイルに組み込めますか？ A. はい。インストーラー実行だけで既存ブックに追加できます。」
  8. ステップ⑧購入時お願い（注意事項）: 箇条書き4-6項目。必須項目: データバックアップ推奨 / 対応範囲外の明示 / 規約違反用途NG / 返金不可 / カスタムオプションは購入前相談。

3-5. 完成文章の最終チェック手順

  1. 字数チェック: タイトルは 「ます」抜きで半角25字以内、キャッチコピーは 半角30字以内。管理画面で実測せよ（エディタのカウントは信用するな）。
  2. 景品表示法チェック: §2-4 の照合手順5ステップを全部実行。
  3. 構成欠落チェック: 3-2 の8ステップ全部が含まれているか目視確認。抜けがあれば追加。
  4. 価値フレームワーク照合: docs/ai-chatbot-value-framework.md の訴求禁止領域に引っかかっていないか確認（AIチャットボット出品の場合）。
  5. マスター承認: 上記4点クリア後、マスターに提示して承認を得る。承認なしでココナラ公開するな。
