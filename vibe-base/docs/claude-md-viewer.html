§4. 開発ルール L29-32 (4行)
  • 命名: kebab-case必須。日本語・スペース・大文字（拡張子除く）禁止
  • 三打席ルール: 同一箇所3回失敗→コミット→memory.md記録→引き継ぎ要請
  • 横断チェック: バグ修正時、同パターンを全ファイル検索し一括修正
§5. AIセルフガバナンス L34-41 (8行)
  • フェーズゲート: ゲート種別タスクではマスター判定なく次フェーズに進まない
  • 先行バリデーション: 変更前に本憲法（スコープ・禁止事項）を照合
  • 能力限界の事前申告: 未検証を「確認済み」と報告禁止
  • 混乱検知: 否定的FB 1回で全停止→整理→報告
  • Check-in義務: セッション開始時に memory.md を読み、前回の未解決事項を把握せよ
  • 製品参照義務: 製品作業時は自治憲法 + PC表を読め
  • PC表連動: タスクの状態を変更したら、対応するPC表を同一コミット内で更新せよ
  • HTML提示義務は MEMORY.md に移動（v4.5）
§6. 禁止事項 L43-46 (4行)
  • mainへの --force push / シークレットのコミット / archive/無断削除
  • 自分が開かれたディレクトリ範囲外のファイルを無断で変更すること
  • 未検証を「動作OK」と報告
