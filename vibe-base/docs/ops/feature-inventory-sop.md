# 機能棚卸し表 SOP v1.0

> 全プロダクト共通。該当タイミングで必ず作成・照合すること。

---

## 1. 作成目的

### 何のために作るのか
プロダクトに実装された全機能を1行1機能で一覧化し、「動くか・いくらかかるか・何が止めているか」を一目で把握する表。

### いつのタイミングで使うのか
| タイミング | 用途 |
|-----------|------|
| P1ゲート前 | 全機能の実装漏れ・API依存・ブロッカーを洗い出す |
| P2ゲート前 | 本番環境で全機能が実行可能か照合する |
| セッション冒頭（機能追加後） | 新機能を追記し、既存行の状態を更新する |
| コスト見直し時 | API課金の総額を把握し、無料枠超過リスクを検出する |

### これを使うとどんなメリットがある？
1. **抜け漏れ防止:** 実装したが動かない機能、動くが課金される機能を見落とさない
2. **ブロッカー可視化:** 外部依存（API審査・キー設定等）で止まっている機能が一目で分かる
3. **コスト予測:** 機能単位の課金額が明示されるため、ユーザー数増加時の費用を即算出できる
4. **引き継ぎ資料:** 次のエージェントが「何が動いて何が動かないか」を即把握できる

## 2. 表フォーマット

HTMLテーブルで作成。保存先: `products/{product}/tmp/feature-list.html`

### 列定義（8列）

| 列 | 列名 | 記載内容 | 記載ルール |
|----|------|---------|-----------|
| 1 | # | 通し番号 | 1から連番。カテゴリ見出し行は番号なし |
| 2 | 機能名 | 機能の短い名前 | 動詞+目的語。20文字以内 |
| 3 | 何の機能か（素人向け） | 技術用語なしの説明 | API名・DB名・フレームワーク名を使わない。ユーザー視点で書く |
| 4 | 実装 | 実装状態 | `済` / `未` の2択 |
| 5 | 実行可能 | 今この瞬間に動くか | `可` / `条件付` / `不可` の3択 |
| 6 | API種類 | 使用する外部APIの正式名称 | 外部API不使用なら「なし(DB保存)」等の理由付き。複数APIを叩く場合は全て列挙 |
| 7 | 実行時コスト | 1回あたりの課金額 | `$0` or `$X.XX/1000回` 等の単価表記。無料枠内なら「実質$0」+上限値 |
| 8 | 発火タイミング | いつ実行されるか | 「ユーザーが○○ボタン押下」「Cron毎日HH:MM」「ページ読み込み時に自動」等。ブロッカーがあれば赤字で「要: ○○」を併記 |

### カテゴリ見出し行
- 機能をカテゴリごとにグルーピングし、見出し行（colspan=8）で区切る
- カテゴリ名は自由。プロダクトの構造に合わせる
- 全機能が停止中のカテゴリには見出しにその旨を明記する

### 状態バッジの色分け

| バッジ | 色 | 用途 |
|--------|-----|------|
| 済 / 可 / $0 | 緑 | 問題なし |
| 条件付 | 黄 | 外部設定で動くが未設定 |
| 不可 / 未 | 赤 | ブロッカーあり |
| $X.XX | オレンジ | 課金発生 |

## 3. 作成手順

1. 全APIルート・コンポーネント・cron・ユーティリティを実際に読む（推測禁止）
2. 1機能1行で全件列挙する。まとめない
3. 各行の8列を埋める
4. `products/{product}/tmp/feature-list.html` に保存
5. ローカルサーバーでURL提示し、マスターに確認を取る

---

## 4. 照合手順（更新時）

1. 既存の `feature-list.html` を読む
2. 前回からの差分（追加・削除・状態変更）を特定する
3. 該当行を更新する。行の追加・削除があれば通し番号を振り直す
4. マスターに差分を報告する
