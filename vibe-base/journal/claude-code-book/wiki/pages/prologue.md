# プロローグ

## 私はエンジニアではありません

まずそこから書かないといけません。

プログラムを書いたことがない、というわけでも完全にはないのですが、
フロントエンドとバックエンドの違いをちゃんと説明できるようになったのは、
Claude Code を使い始めてから半年も経っていません。
データベースとは何か、API とはどういうものか、React と Vue のどちらが何に向いているか——
そういったことを「なんとなく分かる」程度になったのも、つい最近のことです。

そんな私が、複数の個人開発プロダクトを動かしています。
AI が書いたコードが本番で動いています。
これが現実です。すごいことだと思います。でも、楽な話でもありませんでした。

---

## 最初の1か月 ― Antigravity という遊び場

Claude Code を始める前に、私は別のツールを使っていました。
Google の Antigravity（当時のサービス名でそう呼んでいました）です。

あの1か月は、正直なところ「遊び」でした。
「AIにこう言えばこんなものが作れる」という感覚をつかむ時期。
ポンポンと指示を出して、それっぽい画面が表示されて、「すごいな」と満足する。
実際に動くものを作っていたかどうかは怪しいですが、少なくとも楽しかった。

ただ、その楽しさには天井がありました。

作ったものが積み重ならないのです。今日作ったものを明日続けようとすると、
AIは前回の文脈を覚えていない。同じ説明をもう一度する。もう一度作り直す。
「昨日の続き」ができない道具というのは、個人の趣味ならいいのですが、
本格的に何かを作ろうとした瞬間に壁になります。

そのころの私は、いくつかのアイデアを「なんとか形にしたい」という状態でした。
モバイルオーダーシステム、シフト管理アプリ、クチコミ分析AI……。
趣味の延長で始めたものが、だんだん「本当に使えるものにしたい」という欲求に変わっていった。
Antigravity ではその欲求に追いつけなかった。それが Claude Code に移った理由です。

---

## 分からないまま作りまくった日々

Claude Code に移ってからの最初の数か月は、
「分からないまま作る」という日々でした。

UI はどうあるべきか。フロントエンドのライブラリはどれを選ぶべきか。
バックエンドのサーバーはどこに置くのか。データベースはどう設計するのか。
API とはそもそも何か。

全部、後から知りました。いや、今でも完全には分かっていません。
でも、Claude Code に「こういうものを作りたい」と伝えると、Claude が全部書く。
私は動作確認をして、「ここが違う」「こっちの方がいい」と返す。
その往復で、何かが動くものができていく。

振り返ると信じがたいのですが、初期の数週間で
React + PocketBase のモバイルオーダーシステム、
Oracle Cloud に乗っかったサーバー構成、
Vercel にデプロイされた複数のウェブアプリ——
こういったものが次々と出来上がっていきました。

「エンジニアでなくてもアプリが作れる」という話は、本当でした。
ただし、ここで話を終わりにしてしまうと、重要なことを隠すことになります。

---

## 一番困ったこと ― 日を跨ぐと前に戻る

最初の壁は、想像していた種類のものではありませんでした。

コードが書けない、とか、技術が難しい、とかではなく——

**日を跨ぐと、開発が後戻りする。**

これが一番きつかった。

1日目に決めたことを、2日目の Claude は知らない。
前のセッションで「この方針でいく」と決めたことを、次のセッションで別の方向に進める。
「前回こうしましたよね」と伝えても、記録がなければ Claude には分からない。
そして私自身も、数日前に何をどうしたか、完全には覚えていない。

こういうことが積み重なると、開発が螺旋状に後退していきます。
直したつもりのバグが戻ってくる。決めたはずの設計がまた議論になる。
「前もやったはずなのに」という感覚が、だんだん慢性化してくる。

この状態は、Claude Code が悪いわけではありません。
AI は記憶を持たない。それはそういうものです。
問題は私の側にありました。**AI というマシンをちゃんと管理していなかった**のです。

---

## 気づいたこと ― バイブコーディングの本質

YouTube や SNS で「Claude Code で個人開発が楽になった」という話を目にします。
あれは嘘ではありません。確かに楽になります。

ただ、「楽になった」の意味が、見る人によって違います。

個人が遊び感覚でプロトタイプを作るなら、Claude Code は本当に楽です。
ざっと指示して、動くものが出てきて、また指示する。それで十分。

でも本気で何かを作ろうとしたとき——
複数のプロダクトを並行して動かしたいとき、
日をまたいで開発を継続したいとき、
複数の AI に役割分担させて効率を上げたいとき——

そこには「管理」が必要です。

AIというマシンは、適切に管理しないと暴走します。
コードの世界でもハルシネーション（事実と異なることを正しいかのように伝える現象）は起きます。
「修正済みです」と報告されたバグが、実は直っていなかった。
「確認しました」と言われた内容が、実際には確認されていなかった。
こういうことが、現実に起きます。

それと、トークン問題というのもあります。
Claude Code には1回の会話で処理できる情報量に上限があります（これをトークンと呼びます）。
長いセッションを続けていると、AIが過去の文脈を読み込めなくなる。
そうなると、ちぐはぐな回答が増えてくる。
この問題への対処も、管理の一部です。

私が「vibe-base」という仕組みを作ったのは、この「管理」をちゃんとやるためでした。

---

## この本で書くこと

この本は、私が Claude Code を使って個人開発を続けてきた2か月間の記録です。
成功談だけではありません。失敗も、撤退も、「なぜこうなったのか分からなかった」という混乱も書きます。

3つのことを伝えたいと思っています。

1つ目は、Claude Code はすごい道具だということ。
エンジニアでない私が複数のプロダクトを動かせているのは、事実です。

2つ目は、でも甘くない、ということ。
SNS で言われるほど簡単ではありません。個人の遊びレベルならいいのですが、
本気でやるなら AI というマシンを管理する必要があります。

3つ目は、だから私はこうした、ということ。
「vibe-base」という共通基盤と、「CLAUDE.md」という AI への憲法を作った。
その話を、なるべく具体的に書こうと思います。

技術的な解説書ではありません。
同じように「よく分からないまま始めた」人に、「こういう道もあった」と伝えるエッセイのつもりです。

それでは、始めます。
