## C. 公式の原文（削らずに残す。次の AI が孫引きしないため）

**hook が要る根拠**（[best-practices](https://code.claude.com/docs/en/best-practices) §Set up hooks）:

> Use hooks for actions that must happen every time with zero exceptions.
>
> Hooks run scripts automatically at specific points in Claude's workflow. Unlike CLAUDE.md instructions which are advisory, hooks are deterministic and guarantee the action happens.

**「踏まえているか」を判定する公式機構**（同 §Give Claude a way to verify its work）:

> Once the check exists, decide how hard it gates the stop:
>
> * **In one prompt**: ask Claude to run the check and iterate in the same message, as in the table above.
> * **Across a session**: set the check as a `/goal` condition. A separate evaluator re-checks it after every turn and Claude keeps working until it holds.
> * **As a deterministic gate**: a Stop hook runs your check as a script and blocks the turn from ending until it passes. Claude Code overrides the hook and ends the turn after 8 consecutive blocks.
> * **By a second opinion**: a verification subagent or a dynamic workflow that checks its own findings has a fresh model try to refute the result, so the agent doing the work isn't the one grading it.

**`/goal` の実体**（[/en/goal](https://code.claude.com/docs/en/goal) §How evaluation works）:

> `/goal` is a wrapper around a session-scoped prompt-based Stop hook. Each time Claude finishes a turn, the condition and the conversation so far are sent to your configured small fast model, which defaults to Haiku. The model returns a yes-or-no decision and a short reason. A "no" tells Claude to keep working and includes the reason as guidance for the next turn.
>
> It does not call tools, so it can only judge what Claude has already surfaced in the conversation.

**B-4 の代わりに実在した記述**（best-practices §Add an adversarial review step）:

> A reviewer prompted to find gaps will usually report some, even when the work is sound, because that is what it was asked to do. Chasing every finding leads to over-engineering: extra abstraction layers, defensive code, and tests for cases that can't happen.

公式が言っているのは「甘くなる」ではなく **「過剰に指摘する」**。**前セッションの検証パネル3巡・空転はこの原文がそのまま当たっている。**

**`type:"prompt"` hook の限界**（[hooks reference](https://code.claude.com/docs/en/hooks.md)）: timeout（既定30秒）・JSON パース失敗は "non-blocking error … execution continues" ＝ **fail-open 固定・設定で変更不可**。この一点だけは前セッションの懸念が正しい。ただし判定を諦める理由にはならない。
