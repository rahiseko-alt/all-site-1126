## 4. 現行 CLAUDE.md v5.1 のうち、v1.0 から骨格が変わっていない部分

原本: `CLAUDE.md`

> ## §0. 概要
> - **Vibe-Base:** 複数のAIエージェントが協調して開発を行うための共通インフラ
> - **作業ディレクトリ:** 1フォルダ=1エージェント。自分の作業ディレクトリ範囲外を無断で編集するな
> - **運用:** シンガーソングライター型（各プロダクトが企画→保守を自律完結）

> ## §4. 開発ルール
> - **命名:** kebab-case必須。日本語・スペース・大文字（拡張子除く）禁止
> - **三打席ルール:** 同一箇所3回失敗→コミット→MISSION_LOG記録→引き継ぎ要請
> - **横断チェック:** バグ修正時、同パターンを全ファイル検索し一括修正

注目点:

- §0「1フォルダ=1エージェント」は v5.1 で記述が強化されたが、思想は Session 1 の「各エージェント作業ディレクトリを整備した」と直結している
- §4 の kebab-case は v1.0 そのまま（2か月間一字一句変わっていない可能性が高い）
- §0「運用:シンガーソングライター型」は後年の追記（v4.0 以降の product-cycle P0→P4 を踏まえた表現）

# 抽出者メモ

- **v1.0 の骨格は「命名」「縄張り」「台帳」の3点。** それ以上を書いていないのがポイント。メタルールもセルフガバナンスもまだ存在しない
- **v1.0 の直後に v1.1〜v1.8 が集中（約10日間で8リビジョン）。** ここで規律条文が一気に追加された。思想は v1.0 で決めきっていて、追加作業は「守らせる工夫」に終始している
- **「1フォルダ=1エージェント」は条文としての明記は後年だが、実装としては v1.0 初日から `agent-ag/*` の形で存在した。** 条文化が遅れたのは「当たり前すぎて書く必要を感じなかった」の疑いが強い（憶測。根拠なし）
- **MISSION_LOG の「直近5件制」は v1.1 で追加。** つまり初版は「全部残す」設計だった。容量破綻の兆候が出てから直近N件+アーカイブ方式に切り替わっている
- **Chapter 2 で書く範囲は「v1.0 時点で何があったか」に絞る。** v1.8 以降の AIセルフガバナンスや v3.0 のメタルールは Chapter 3（自治憲法を書く）以降に譲る
- **根拠のない箇所:** v1.0 の原文そのものは現存ファイルから直接取得できなかった（archive に v1.0 の .md 本体は残っていない）。条文の表現は revision-history.md からの逆算で再構成している。Chapter 2 本文で v1.0 の条文を引用する際は「こう書いてあった」ではなく「こういう効果があった」という側から書く
