本物照合ファーストの3D/画像アセット生成工程

調査日: 2026-06-06
調査テーマ: 「変なものを作ってから本物に近づける」ではなく「本物に近しい設計図を先に作ってから詰める」工程は妥当か
対象: 動物・食品・建造物などカテゴリ横断の生成ワークフロー
主要ソース: Infinigen, BlenderProc, Khronos glTF Asset Auditor, T3Bench, 3DGen-Bench, GPTEval3D/Eval3D
結論: ユーザー案は素人考えではなく、GitHub上の実装・研究ベンチマークと整合する。実務的には「Reference-first / schema-first / multi-view-eval」の組み合わせとして定式化できる。生成前にカテゴリ別の本物照合基準を作らず、出力後に感覚で直す運用は破綻しやすい。

根拠1. Procedural realism は「本物の構造を先にモデル化」する

Infinigen は photorealistic worlds を procedural generation で作るプロジェクトで、個別asset/materialの作り方として Blender UIで設計→ノード/コード化→seed付きFactoryで再生成→繰り返しテストする流れを示している。これは「いったん変なものを出して後から直す」より、対象カテゴリの構造・素材・ばらつきを generator に先に埋め込む思想に近い。

特に ImplementingAssets.md は、asset generator を Factory として定義し、ランダム化パラメータを持たせ、Blender UIを視覚デバッグに使って繰り返し検証する前提になっている。

根拠2. Photorealistic pipeline は物理・材質・カメラを分離して検証する

BlenderProc は photorealistic rendering pipeline として、物体pose、physics/collision、PBR material、lighting、camera、segmentation等を分離した工程で扱う。つまり、写りが悪いから後から色だけ直すのではなく、物体配置・物理接触・材質・照明・カメラを別軸の検証対象にする。

根拠3. 3D commerce では schema pass/fail が先にある

Khronos glTF Asset Auditor は glTF asset を JSON schema の要件に照らして Pass/Fail/Not Tested にする。検査項目には file size, triangle count, material count, clean origin, beveled edges, non-manifold edges, dimensions, PBR safe colors, texture resolution, texel density, UV overlap/gutter などがある。

重要なのは「見てから何となく直す」ではなく、先に schema を作っておき、品質の一部を機械判定すること。

根拠4. 3D生成評価は単一スコアではなく多軸・多視点

T3Bench は text-to-3D の評価で multi-view images を使い、subjective quality と text alignment を分けて評価する。3DGen-Bench は human preference dataset を持つ包括ベンチマーク。Eval3D や GPTEval3D 系は、人間選好に近い細粒度評価を目指す。

ここから、カテゴリ横断運用では「正面1枚で何となくOK」では足りず、multi-view、構造、材質、意味整合、技術品質を分ける必要がある。

導出フレーム: Asset Realism Contract

契約項目内容例: ドーナツ
実物構造対象が実物として成立する部品構成・接続・内外関係生地本体、穴、表面コーティング、垂れ、スプリンクルは別部品
カテゴリ固有の破綻禁止そのカテゴリで一発アウトになる条件穴が円盤で塞がる、コーティングが板状、食品がプラスチック質
材質PBR範囲roughness/specular/base color/SSS/normal/bump等の許容帯グレーズは薄膜光沢、生地は多孔質で粗い、砂糖菓子は微光沢
幾何チェックmanifold、厚み、bevel、接触、交差、スケール、重力方向コーティングは生地曲面に沿い、外周/穴周りから垂れる
参照照合実物/高品質CGの参照画像を複数角度で照合上面、斜め、断面/穴周辺、接写の4系統
multi-view QA最終前に複数視点で同じ破綻がないか確認正面で良くても穴内側・外周垂れを別視点で確認

推奨工程

  1. カテゴリ選定: 動物/食品/建造物などを先に分類し、カテゴリ別 checklist を選ぶ。
  2. Reference board: 5〜12枚の実物/高品質CG参照を集め、形・材質・破綻例を分ける。
  3. Asset Realism Contract: 生成前に、部品構造、禁止破綻、PBR範囲、幾何条件、multi-view視点を文書化する。
  4. First build: 参照構造に近いベースを作る。出力後に大改造する前提にしない。
  5. Gate QA: 各段階で「本物として成立するか」をPass/Failする。Failなら次工程へ進まない。
  6. Polish: 合格したベースだけ、照明・色・細部密度・ノイズを詰める。

今回の失敗への適用

ドーナツでは Contract がなかったため、「コーティングは生地表面に密着した薄膜である」という最重要条件を落とした。smooth, Cycles, sprinkles など周辺改善で PASS してしまったが、カテゴリ固有の破綻禁止を先に置いていれば smoke 段階で停止できた。
