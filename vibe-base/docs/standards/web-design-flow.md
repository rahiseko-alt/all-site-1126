# WEBデザイン手順化フロー（正本）

> 本書は WEB/LP デザインを毎回高品質に作るための **唯一の正本**。skill `/web-design` と rule `web-design.md` / `lp-design.md` は本書を参照する（重複定義禁止・Reference-over-Redundancy）。
>
> 確立思想＝「**良い参照から作る ＋ judge ＋ マスターの目**」。手順スキルも機械ゲートも AI の本能には勝てない（[[no-ai-self-discipline]]）。機械ゲートは廃止し、judge（生成と評価の分離）＋マスター目視で品質を担保する。

## 判定軸＝骨格パラダイム（最重要・これがすべての基準）

- **金太郎飴**＝全幅ブロックを定型順で縦に"通過"するだけ。
- **脱・金太郎飴**＝スクロール・操作・次元のいずれかを"再発明"している。
- **技術・アニメ機構の有無は判定に使わない**（機構たっぷりでも骨格が定型なら金太郎飴）。
- ものさし実例（golden set）→ `docs/standards/design-yardstick/`：ダメ＝`index`/`pro-2`/`pro-3`・良＝`pro-1`。

## フロー10ステップ（Double Diamond 骨格）

DD骨格：Discover[発散]=Step1／Define[収束]=Step2／Develop[発散]=Step3-4／Deliver[収束]=Step5-10。各菱形で発散→収束。問題理解を先に。非線形（FAIL時は該当Stepへ戻すループを容認）。

| Step | フェーズ | やること | 出力 |
|------|---------|---------|------|
| 1 | Discover | **コンセプト確定**：依頼主確定なら情報を調べ上げる（ゴール＝依頼主の代表者になり切ってコンセプトを語りつくせる）／曖昧・未定ならマスター指示を仰ぐ。**中身を勝手に決めるな** | コンセプト |
| 2 | Define | **デザインコンセプト確定**：ユーザーが「○○を得られる/○○になれる」を響くメッセージ化 → **冒頭2秒で感じさせる**手法選択（テキスト/アニメ/動画/画像）。2秒以外は補足 | 2秒メッセージ |
| 3 | Develop（発散） | **参考リサーチ**：コンセプトを体現する参考を広く・**実物で**集める（Awwwards/Godly/SiteInspire/Land-book 等・**「見ずに当てる」禁止**）→ 2秒で伝える見せ方（骨格/スクロール/配置）を抽出。Swipe File に追記 | 参考＋抽出メモ |
| 4 | Develop（収束） | **デザインイメージ確定＋ワイヤーフレーム**：参考群を1方向に収束（トンマナ/骨格/操作）→ WF＝構造設計（lo-fi・各セクション配置） | イメージ確定＋WF |
| 5 | Deliver | **実装技術の選定**：Technology Radar（後述）から選択。基準＝コンセプト整合/性能/実装コスト/フォールバック可否。**素CSSのみ禁止＝最新技術最低1つ** | 採用技術 |
| 6 | Deliver | **保守コストの並列リサーチ＋天秤**：採用技術の保守工数（壊れやすさ×対応コスト・外部条件変更で将来動かなくなるリスク）を把握 →「品質 vs 保守コスト」を天秤に最終判断。大前提＝売れなきゃ意味ない＝とにかく良いものを | 保守リスク評価＋採用可否 |
| 7 | Deliver | **開発計画の初期案→選定**：イメージ/WF/技術/保守判断から計画案作成→1つ選定。含む＝初期構築コスト見積（トークン/時間/サブ体数）・スコープ・段取り・着手前マスター提示 | 採用する開発計画 |
| 8 | Deliver | **実装計画の詳細立案＋サブ役割決定**：frontend-engineer-agent 複数並列で変種生成→選定（フォアグラウンド実行・別ファイル pro-1/2/3・各体に共通コンセプト/イメージ/WF/技術・各体に骨格発明点3行報告。体数は Step7 見積連動） | 実装手順＋サブ割当 |
| 9 | Deliver | **実装・検証**：サブ並列で実装 → taste-judge サブ（生成と分離）が rubric（後述）で照合 → PASS/FAIL。FAIL→該当Step戻し。**judgeは助言・決定はマスター** | 実装物＋judge判定 |
| 10 | Deliver→運用 | **マスター確認＋運用改善ループ**：judge通過物をマスターが最終判定・NG→Step戻し。公開後＝FB/パフォーマンスで継続改善（Deliverは終点でなくループ） | 確定・公開・改善記録 |

## Step9 完了判定前：スクショ3構図（必須・偽PASS禁止）

Step9（実装・検証）の完了判定は、ファーストビューのみを見て「良好」と報告してはならない（**偽PASS禁止**）。judge 照合・マスター確認に先立ち、以下を毎回実施する。

**必須3構図**：
1. **desktop full-page**（下部空白・空箱検知）
2. **mobile 375px**
3. **スクロール後**（アニメ・遅延読込・スクロール連動演出の実挙動確認）

保存先パスは毎回明示すること（成果物として残す）。

**撮影ツール呼び分け規約**（3系統併存を統一）：

| ツール | 用途 | 備考 |
|--------|------|------|
| **chrome-devtools**（既定） | 通常のWEB/LPデザイン検証 | `resize_page` → `take_screenshot`（`fullPage`指定） |
| **playwright**（例外） | WebGL・headed 実行が要件の場合のみ | 手順は `memory/feedback_webgl-blindtest-protocol.md` 準拠 |
| **Claude_Preview** | 新規使用は非推奨（廃止はしない・既存運用のみ許容） | — |

## 設定（フロー外・別途固定／随時更新）

### 設定1: 実装技術リスト＝Technology Radar 方式

4リングで分類。リング＝good/bad でなく「採用姿勢」。

| リング | 意味 | 初期 blip |
|--------|------|----------|
| **Adopt** | 既定の第一選択 | GSAP+ScrollTrigger ／ 可変フォント・キネティックタイポ |
| **Trial** | コンセプト合致＋フォールバック前提で投入 | Three.js・WebGL（粒子・シェーダー）／ SVG歪み（feTurbulence・feDisplacementMap）／ Lenis ／ Lottie |
| **Assess** | 評価段階・対応/コスト注意 | View Transitions API ／ CSS Houdini ／ Canvas手組み |
| **Hold** | 新規で着手しない | **素CSSのみ＝最新技術ゼロ（＝金太郎飴の温床）** |

**更新ルール**：案件時＋定期（feed-check / deep-research 連動）で blip 移動・追加。更新者＝司令塔。記録先＝本書（この表を直接編集）。

### 設定2: judge（ものさし）＝LLM-as-a-Judge 方式

参照あり＋pairwise。**rubric は形容詞でなく"確かめる手順"で記述**。golden set に失敗例必須。

**rubric（確かめる手順）**：
1. ヒーローのスクロール／操作／次元に**再発明があるか**（全幅ブロックを定型順で縦に通過するだけ＝FAIL）
2. 最新技術が最低1つ、**コンセプト整合で効いているか**（機構の有無では判定しない＝機構たっぷりでも骨格が平凡ならFAIL）
3. 冒頭2秒でコンセプト／感情が伝わるか
4. 参考実物を見て作った形跡（形式・次元・操作の抽出）があるか
5. モバイル・reduced-motion フォールバックがあるか
6. ものさし照合：`index`/`pro-2`/`pro-3`（FAIL基準）に似ていないか／`pro-1`（PASS基準）の水準か

**golden set**：`docs/standards/design-yardstick/` の4実例（期待ラベル＝index/pro-2/pro-3=FAIL・pro-1=PASS）。
**運用化条件**：judge のラベルがマスターのラベルと 75-90% 一致で運用化。judge は助言・**決定はマスター**。

### 設定3: 知識doc＝Swipe File 方式

恒久の参照DB・"学ぶがコピーしない"。配置＝`docs/swipe-file/`（git追跡・index.html が目次）。市場/競合の `docs/research-bank/` とは別物。

- 1エントリ＝1参考（URL／スクショ／抽出メモ「採用する形式・次元・操作」／タグ）
- タグ（背骨）：コンセプト感情・骨格タイプ（横スクロール/ピン留め/3D/分割等）・業種・技術
- 更新：案件 Step3 のリサーチ成果を毎回追記

### 設定4: サブエージェント運用ルール

`frontend-engineer-agent` 複数並列で変種生成→選定。フォアグラウンド実行（背景は Write auto-deny）。変種ごとに別ファイル。共通コピー/コンセプト/実連絡先を全体に渡す。各体に骨格発明点3行報告。体数は Step7 見積連動。詳細→ `.claude/rules/subagent-ops.md`。

## ダメデザインチェックリスト（提出前自己採点・1つでも該当で提出禁止）
- 縦スクロール骨格だけ
- Inter＋紫青グラデ＋中央3カード＋均一余白（典型金太郎飴）
- 素CSSのみ・最新技術ゼロ
- 2秒で感覚が伝わらない
- 参考実物未確認（記憶で作った）
- モバイル・reduced-motion フォールバック無し
- ヒーローの形式・次元・操作に発明無し
