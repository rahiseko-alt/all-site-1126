# バックエンドホスティング選定の経緯

> **位置づけ:** 開発を中断・再開した際に必ず読み返すこと。なぜこの選択に至ったかの意思決定記録。
> **決定日:** 2026-03-01
> **決定者:** マスター（コウヘイ）

---

## 1. 問題

Sprint 5 UAT 完了後、バックエンド（PocketBase）がマスターのローカル PC 上で動いており、ターミナルを閉じるとアプリ全体が停止することが判明。「いつでも誰でもどこからでもデモ版を触れる」状態にならなかった。

## 2. 要件（マスター指示）

1. **デモ版を常時稼働** — マスターの PC が壊れていても動き続けること
2. **複数アプリ対応** — 今後作る全アプリのバックエンドを集約できること
3. **クライアントがスマホで試用可能** — URLを渡すだけで触れること
4. **買い手が見つかったらバックエンド仕様を変更** — クラウド → Daddy（ローカル）移行が容易であること
5. **バックエンド変更で他機能に影響がある場合は強烈な警告** — 見落とし防止

## 3. 検討した選択肢

| 選択肢 | 月額 | 複数アプリ | 常時稼働 | セットアップ | 判定 |
|--------|------|-----------|---------|-------------|------|
| **PocketHost** | $5/アプリ | $5×N（5個超で$25） | ✅ | 5分 | ❌ 複数アプリでコスト増 |
| **Fly.io** | 無料枠限定的 | 制限あり | △（スリープあり） | 中程度 | ❌ 無料枠が実用的でない |
| **Render** | 無料枠あり | 制限あり | △（永続ディスク有料） | 中程度 | ❌ SQLite永続化に有料プラン必要 |
| **Oracle Cloud Free Tier** | **永久無料** | **何個でも** | ✅ | 数時間（初回のみ） | ✅ 採用 |

## 4. 決定: Oracle Cloud Free Tier

**理由:**
- ARM 4コア / 24GB RAM が永久無料 — 全アプリのバックエンドを1台に集約
- PocketBase を複数ポートで起動すればアプリごとにインスタンスを分離可能
- PocketBase 以外の技術（Node.js, Python 等）も自由に使える
- Daddy（ローカル PocketBase）への移行は `pb_data/data.db` を移すだけ

**トレードオフ:**
- 初期セットアップに数時間かかる（1回限り）
- manifesto §2 の「インターネット断でも動作」はデモ版では非対応（割り切り）
- 買い手が見つかったら、その店舗の要件に応じて Daddy 型かクラウド型かを選択

## 5. ライフサイクル設計

```
Phase 1（今）: Oracle Cloud（デモ版常時稼働）
    ↓ 買い手が見つかる
Phase 2（販売時）: 店舗の要件に応じて選択
    ├─ パターンA: クラウド型（PC不要・簡単導入）
    └─ パターンB: Daddy型（オフライン対応・manifesto完全準拠）
    ↓ 運用開始
Phase 3（販売後）: バックエンド変更時は安全ルール必須
```

## 6. 安全ルール（バックエンド変更時）

バックエンドの接続先・DB構成・認証方式を変更する場合：
1. 影響を受ける全機能をリスト化
2. memory.md 先頭に 🔴 WARNING セクションを設置
3. 変更前・変更後の動作確認チェックリストを明文化
4. 移行失敗時に30分以内で元の構成に戻せるロールバック手順を用意
5. テスト環境で検証後に本番切り替え
