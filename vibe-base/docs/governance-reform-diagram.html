実施した6つの変更

問題

PC表テンプレートが消失

過去作成のテンプレートが未保存。新プロダクト作成時にゼロから作り直し。
対策 #1

テンプレートをproduct-cycle.mdに同梱

SOPファイルに付録として全フェーズ(P0-P4)のPC表テンプレートを追加。コピーするだけで使える。
問題

PC表がdocs/にあり製品エージェントが書けない

タスクを完了する製品エージェントがPC表を更新できない。vibe-base経由でしか更新されない。
対策 #2

PC表をproducts/に移動

docs/*-pc-progress.md → products/*/pc-progress.md。情報を生むエージェントが直接書ける場所に配置。
問題

自治憲法の「完了12/12」が虚偽

自治憲法にフェーズ状態を直接記載 → 自己申告で更新 → PC表と乖離。
対策 #3

フェーズ状態をポインタ化

自治憲法から状態テーブルを削除し「→ pc-progress.md」のポインタのみ記載。Single Source of Truth。
問題

MISSION_LOG・PC表を読む義務がない

CLAUDE.md §5に読み込み義務がないため、エージェントが前回の状態を把握せずに作業開始。
対策 #4

§5にCheck-in義務 + 製品参照義務 + PC表連動を追加

セッション開始時のMISSION_LOG読み込み、製品作業時の自治憲法+PC表読み込み、タスク変更時のPC表同時更新を義務化。
問題

vibe-baseが製品ファイルを編集できない

MEMORY.md P3の「エージェント配下は直接編集しない」制約で、Opusが製品内PC表を更新できない。
対策 #5

P3制約を緩和

「PC表・自治憲法はvibe-base(Opus)からも編集可」を追加。司令塔が直接更新可能に。
問題

クチコミ分析AIにPC表が存在しない

Session 28照合で発覚。「P2完了」申告の実態は#8×, #9×, #13×。
対策 #6

クチコミ用PC表を新規作成

テンプレートから作成し、Session 28の実物確認結果を反映。△/×を正直に記載。
