# ADR 0002: memory ファイル役割分担

**ステータス:** 採用  
**決定日:** 2026-06-06

## 背景

プロジェクトには 2 つの memory 管理ファイルが並存している:

1. `products/learning-suite-kanji/memory.md` などプロダクト固有 memory
2. `~/.claude/projects/.../memory/MEMORY.md`（auto-memory・全セッション自動読込）
3. `vibe-base/memory.md`（手管理・セッション引継ぎ用）

このうち (2) と (3) の役割が不明確なまま運用されており、MEMORY.md が 10.2k tokens（Memory files 全体の 74%）を占めるまで膨張した。

## 決定

### デュアル構造を維持する

| ファイル | 役割 | 内容 |
|---------|------|------|
| `MEMORY.md`（auto-memory） | **永続行動規範** | P1 絶対規律・P1.5 トリガーマップ・参照索引 |
| `vibe-base/memory.md`（手管理） | **セッション引継ぎ** | 現フェーズ・直近 plan path・進捗タスク |

### 統合しない理由

- auto-memory は全プロダクト横断で常時ロードされる（200 行制限）
- vibe-base/memory.md はセッション固有の一時情報を含む
- 用途が異なるため統合すると両方の見通しが悪くなる

## 運用制約

- MEMORY.md は 200 行 / 25 KB auto-trim が発動する前に P3 を手動整理する
- P1 絶対規律 16 項は削除不可
- P3「運用情報（容量圧迫時削減対象）」は適宜削除してよい
- 完遂済みプロジェクト記録は 1 行ポインタに圧縮してよい

## 影響

- Phase 2 (2026-06-06): P3 節削除（9 行）+ Plan Mode 再設計エントリ圧縮（8→1 行）= 16 行削減
