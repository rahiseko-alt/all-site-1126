# CSS Quality Checklist

CSS の設計品質（トークン一貫性・未使用コード・複雑度）を外部ツールで客観計測するチェックリストと手順です。**全プロダクト共通**で使用します（バニラ HTML/CSS・React・Svelte 等のビルド有無を問わない）。

## 1. 静的コードレビュー項目

AI が CSS をレビューする際の必須チェック項目です。

### デザイントークンの一貫性
- [ ] 色は `var(--color-*)` 等の CSS カスタムプロパティ経由で参照され、`#0a0a0a` 等のリテラル色が散在していない。
- [ ] フォントサイズ・余白（spacing）・角丸（border-radius）も同様にトークン化されている。
- [ ] 同一意味の値が複数のリテラルで重複していない（例: `#fff` と `#ffffff` と `white` の混在）。

### セレクタ・詳細度
- [ ] `!important` が乱用されていない（詳細度の破綻サイン）。
- [ ] ID セレクタでのスタイル指定を避け、詳細度が一定の範囲に収まっている。
- [ ] 未使用セレクタが残っていない（下記 Coverage で実測）。

## 2. Chrome DevTools Coverage 手順（未使用 CSS/JS の実測・無料・インストール不要）

未使用の CSS / JS を行単位で検出する。バニラ構成でもビルド構成でもそのまま動く。司令塔（人間）に以下の手順を指示してください。

```text
1. 対象ページを Chrome で開く（ローカルサーバ経由。file:// でなく http://localhost 推奨）
2. F12 で DevTools を開く
3. Ctrl+Shift+P（Mac は Cmd+Shift+P）でコマンドメニューを開く
4. "Show Coverage" と入力して Enter
5. Coverage パネルの左上のリロードアイコン（●）をクリックして記録開始
6. ページを操作（スクロール・クリック）して全インタラクションを発火させる
7. 各ファイルの "Unused Bytes" と未使用率（%）を確認する
```

判定の目安:
- [ ] CSS の未使用率が極端に高くない（目安: 50% 超なら削減余地を検討）。
- [ ] ファーストビューに不要な大きい CSS/JS が読み込まれていない。

※ Coverage は「そのセッションで実行された範囲」を計測する。全インタラクションを発火させてから読むこと（操作前のリロード直後の数値は過大に出る）。

## 3. Project Wallace 手順（CSS 品質スコア・150+ メトリクス・無料・サインアップ不要）

CSS の構造・複雑度・トークン一貫性を 150+ メトリクスでスコア化する。

### 方法 A: Web 版（context 消費ゼロ・最速）

```text
1. https://www.projectwallace.com/analyze-css を開く
2. 対象の CSS（style.css の中身）をテキストエリアに貼り付ける
3. Analyze を実行
4. 以下を確認する:
   - Health score（CSS 全体の健全性スコア・1 つの数値）
   - Colors / Font-sizes / Spacing のユニーク数（トークンが少数に収束しているほど良い）
   - Selector complexity / Specificity（複雑度・詳細度の分布）
```

判定の目安:
- [ ] Health score が著しく低くない。
- [ ] ユニークな色・フォントサイズの数が膨張していない（デザイントークン化されていれば少数に収束する）。
- [ ] 詳細度の最大値が突出していない。

### 方法 B: ローカル npm（CI 自動化したい場合のみ）

```bash
npm install --save-dev @projectwallace/css-analyzer
```

`@projectwallace/css-analyzer` が `analyze()` 関数をエクスポートする。Node スクリプトから CSS 文字列を渡してメトリクス JSON を取得し、しきい値判定に使う。

## 4. 運用注記

- このチェックリストの 2・3 は **外部 Web サービス／ブラウザ組み込み**であり、Claude の context（トークン）を一切消費しない。
