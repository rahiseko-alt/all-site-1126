This page is a reproduction of the ASCII play manual, written for this site. The runtime is the open-source play.core by ertdfgcvb (Apache License 2.0). It is an homage to play.ertdfgcvb.xyz.

Play: About

A live-coding environment in the browser whose only output is text. Each frame, a small program decides which character goes into every cell of a grid.

The interface is deliberately reduced to three things: the output, the code and a menu. No line numbers, no panels, no settings dialog — everything else is done in code.

Feedback is given with the browser’s own alert and confirm dialogs. Small commands (“bangs”) can be typed straight into the editor. Programs can be saved in the browser’s local storage, or uploaded to the server to get a permalink. Uploading needs no account.

Play: Background

The model is close to a GLSL fragment shader: instead of pixels there are character cells, and a function is called for each of them. A maximised browser window holds roughly 5,000 to 8,000 characters, drawn at up to 30 frames per second.

By default the output is real DOM text: it can be selected, copied and is rendered by the browser’s text engine. A canvas renderer is available too.

API: Modules

A program is an ES6 module. There are no globals; the runner looks for these exports, all of them optional:

bootcalled once, before the first frame
precalled once per frame, before main
maincalled once per cell, per frame; returns the cell’s content
postcalled once per frame, after main
settingsobject overriding the runner defaults
dataany object, passed to every function

The smallest program:

export function main() {
	return '?'
}

API: Function signatures and parameters

export function boot(context, buffer, data) {}
export function pre(context, cursor, buffer, data) {}
export function main(coord, context, cursor, buffer, data) {}
export function post(context, cursor, buffer, data) {}
coord
x, ycolumn and row of the cell, origin top left
indexy * cols + x, the cell’s index in the buffer
context
frameframe number
timetime in milliseconds
cols, rowssize of the grid
width, heightsize of the container element in pixels
metricsaspect, cellWidth, lineHeight, fontFamily, fontSize, _update()
settingsthe active settings
runtimecycle (local run counter) and fps (measured)
cursor
x, yhovered cell, fractional
pressedpointer is down
pprevious frame’s {x, y, pressed}
buffer
A flat array with the state of every cell, accessed with buffer[coord.index]. It is not cleared between frames — only on start and resize — which is what simulations rely on. Writing to it in pre or post is expected.

API: The return object in main()

main returns either a single character or an object:

return {
	char            : 'A',
	color           : 'black',
	backgroundColor : 'white',
	fontWeight      : 400   // 300, 400 or 700 online; other values snap
}

An object is merged into the existing cell. The number 0 is printed as “0”; any other falsy value results in an empty cell.

API: Boot

boot runs once and does not know about later resizes. To keep your own per-cell data, detect a change of cols / rows in pre and rebuild it there.

API: Data

export const data = {
	counter : 0
}

export function main(coord, context, cursor, buffer, data) {
	return data.counter
}

The exported object is handed to every function as the last argument, and can also be changed from outside the runner.

Live coding: Bangs

Type one of these anywhere — a comment is a good place. It runs about 200 ms after typing, no Enter needed.

?helpopen this manual (?abc does the same)
?lsdopen the local storage directory
?immediate on|offimmediate mode
?video night|dayeditor theme
?newnew document (unsaved changes are lost)
?savesave locally
?fullscreenfullscreen, Esc to leave

For programs saved locally, !immediate on and !video night are read when the program is loaded.

Live coding: Save and upload

Save stores the program in this browser’s local storage under a timestamp, which becomes its URL: /#/local/<timestamp>. Saving again from that URL overwrites it. All local programs are listed in the L.S.D.

Share uploads the program and redirects to a new permalink, /#/<number>. Every upload creates a new permalink. An upload needs an @author (other than “ertdfgcvb”), a @title and at least one line of code:

/**
@author Your name
@title  Your title
@desc   Optional description
*/

	.catch(err => console.warn(err))

Notes: On performance

The text renderer draws the buffer row by row. Every change of color, background or weight along a row adds an inline element, so programs with a lot of horizontal style changes get slow; vertical changes are cheap. Keeping the grid small helps too.

Notes: Technical

The editor content is encoded with TextEncoder, turned into a Blob URL and imported dynamically. The only preprocessing is a rewrite of import paths to this origin.

Output uses two iframes: a new program is built in the hidden one and swapped in after its first frame. A broken program therefore leaves the last working one on screen; errors are reported back and marked in the editor.

The runner waits for document.fonts.ready plus three animation frames before measuring the font (WebKit bug 217047). Other WebKit issues: 218275 and 218284 (no line numbers / no error events from modules), 240213 (measureText rounding), 225695 (line-height rounding).
