## 運用ルール（純増停止・本ファイルの位置づけ）

- **本ファイルはマスター反復指示・行動規範 feedback の単一追記先（正本）である。**
- 今後マスターから繰り返し指示・訂正・好みを受けたら、**新規 `feedback_*.md` / `.claude/rules/*.md` / `docs/ops/*.md` を作らず**、本ファイル Part2 の該当 theme に追記する（逐語保全）。
- 既存の散在 `feedback_*.md`（auto-memory 配下 ~30 個）は、参照されたタイミングで本ファイルへ吸収し消し込む（一括移管はしない・触れた時に統合する Refactor-on-Write）。
- 機械化が済んだパターンは Part1 に ✅ を付け、Part3「仕組み化済み」へ移す。
- 新規ルールファイルの作成は「本ファイルに収まらない構造（hook / script / skill 本体）」に限る最終手段。

## Part 4. 推奨アクション（司令塔の判断・丸投げしない）

繰り返しの「強度 × 機械化ギャップ」で見て、**最優先で仕組み化すべきは 3 件**:

1. **commit 前 verify-agent 必須 hook**（Part1 #1）— 「やった≠状態」「タグ≠中身」が全期間で最頻・最強度。orchestration 規律3 を口頭から pre-commit 機械ゲートへ昇格すれば、誤完了宣言が構造的に止まる。
2. **plan-finalize に「受入条件 Y/N 禁止＝検証コマンド/数値必須」+「大ゴール不変欄」**（Part1 #2）— plan 品質の不満が全期間で反復。機械検査可能。
3. **output-style.md 新設（一言/番号回答・補足は要請後・要約禁止）**（Part1 #4,#5）— 毎セッション違反する出力粒度を、常時注入の行動既定で底上げする。
