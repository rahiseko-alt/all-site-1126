## 0. 動画配信戦略（製品単位で1回策定）

個別の動画を作る前に、**製品ごとの配信戦略**を策定する。
策定済みの場合、個別動画の§1 A/Bは戦略テーブルから自動決定される。

### 0.1 ファネルと動画の役割

```
認知（知ってもらう）→ 興味（LPに来てもらう）→ 行動（登録してもらう）
```

動画は3種類に分かれる:

| 種類 | 役割 | 配信面 | 目安尺 |
|------|------|--------|--------|
| **入口動画** | 認知〜興味。存在を知らせ、LPへ誘導する | Instagram Reels / TikTok / YouTube Shorts / X | 7-30秒 |
| **出口動画** | 行動。LP上で製品の価値を伝え、登録を後押しする | LP埋め込み | 30-90秒 |
| **分岐動画** | 成果に応じて追加。特定の切り口・別プラットフォームへの展開 | 成果を見て決定 | 動画種別に準拠 |

### 0.2 最低構成（これだけ作れば配信を開始できる）

| 順番 | 動画 | 目的 | 配信面 | 次のアクション判断 |
|------|------|------|--------|--------------------|
| **1** | **入口動画 1本目** | 認知→LP遷移 | Instagram Reels | 投稿後、リーチ数/LP遷移数を計測。反応が良ければ同じ切り口で2本目、悪ければ切り口を変える |
| **2** | **出口動画 1本目** | LP上でCVR向上 | LP埋め込み | LP訪問→登録の転換率を計測。動画あり/なしでCVR比較 |

この2本が揃った時点で「動画→LP→登録」の導線が成立する。

### 0.3 分岐判断（2本完成後）

| 条件 | 次に作る動画 |
|------|-------------|
| Reelsのリーチが良い（目安: フォロワーの2倍以上） | 同プラットフォームで切り口を変えた入口動画2本目 |
| Reelsのリーチが悪い | 別プラットフォーム（X or TikTok）で入口動画を試す |
| LP遷移は多いがCVR低い | 出口動画を改善（別の訴求軸で作り直し） |
| LP遷移もCVRも良い | 分岐動画で別切り口を展開（機能別/ターゲット別/季節別） |

### 0.4 配信戦略テーブル（製品ごとに作成し、自治憲法に記載）

```markdown
| # | 動画名 | 種類 | 目的 | 配信面 | 切り口 | 状態 |
|---|--------|------|------|--------|--------|------|
| 1 | （名前） | 入口 | 認知→LP遷移 | Reels | （差別化ポイント） | 未着手/制作中/配信中 |
| 2 | （名前） | 出口 | CVR向上 | LP埋め込み | （製品デモ） | 未着手/制作中/配信中 |
| 3 | （名前） | 分岐 | （分岐判断による） | （判断による） | （判断による） | — |
```

> **§1との関係:** 配信戦略テーブルが存在する場合、§1のA（目的）とB（配信面）はテーブルから引く。C-Gのみ個別に確定する。

## 1. 事前決定事項（動画ごとに制作開始前に全て埋める）

進行表作成前に以下を確定させる。曖昧なまま進行表に入るな。
**A/Bは§0配信戦略テーブルから引く。** 戦略テーブルが未策定の場合のみQAで確定。

| # | 決定事項 | 入力元 | 備考 |
|---|----------|--------|------|
| A | **目的** | §0配信戦略テーブル | 認知 / 興味喚起 / 行動 |
| B | **配信面** | §0配信戦略テーブル | §2プラットフォーム仕様を自動参照 |
| C | **ターゲット** | P0 S1のターゲット定義 | 頭の中の言葉（VoC）まで掘る |
| D | **CTA** | 目的から導出 | 認知→プロフィール / 興味→LP / 行動→登録ボタン |
| E | **トーン** | QA or 前回踏襲 | 緊迫感→安心 / 共感→解決 / 驚き→納得 |
| F | **音声戦略** | §2プラットフォーム仕様から導出 | ミュート前提 or 音声重視 |
| G | **素材方針** | QA | Replicate画像 / 実写 / スクリーンキャプチャ / テキストのみ |

> **テロップの入力ソース（絶対ルール）:**
> テロップ・コピーに使う主張・数字・機能名は**現在のLP記載内容+仮説テーブル（✅確認済みのみ）**から引く。
> 古い設定ファイル・過去の動画・CLAUDE.md の市場調査データからのコピーは禁止。
> LPと動画の主張が食い違うと「嘘がないか」の原則に抵触する。
>
> **LP変更時の動画更新トリガー:**
> LPの訴求（ヘッドライン・機能・価格・条件）が変更された場合、配信中の全動画の進行表を再照合する義務がある。
> LP変更のコミット時に、該当製品の配信戦略テーブルを確認し、影響する動画を特定→進行表のテロップを修正→再レンダリング。

## 2. プラットフォーム別仕様

| 配信面 | アスペクト比 | 解像度 | 推奨尺 | 最大尺 | 音声 | 備考 |
|--------|-------------|--------|--------|--------|------|------|
| Instagram Reels | 9:16 | 1080x1920 | 7-15秒 | 90秒 | ミュート前提で設計 | テロップ必須。セーフゾーン上下15%に重要要素置くな |
| Instagram Stories | 9:16 | 1080x1920 | 5-15秒 | 60秒 | ミュート前提 | 下部20%にCTAスワイプ領域。テキスト被せるな |
| TikTok | 9:16 | 1080x1920 | 15-30秒 | 10分 | 音声重要 | 冒頭フック最重要。トレンド音源の利用を検討 |
| YouTube Shorts | 9:16 | 1080x1920 | 15-30秒 | 60秒 | 音声重要 | タイトル・説明文でSEO |
| YouTube（横型） | 16:9 | 1920x1080 | 2-5分 | 制限なし | ナレーション推奨 | サムネイルが別途必要 |
| LP埋め込み | 16:9 | 1280x720 | 30-90秒 | 3分 | ミュート自動再生+音声ON切替 | ファイルサイズ注意。LCP悪化させない |
| X（Twitter） | 16:9 or 1:1 | 1280x720 | 15-30秒 | 2分20秒 | ミュート前提 | 自動再生。冒頭で目を止める |

> **テスト段階:** 全配信面で 720p × 3-5秒。本番品質は最終レンダリング時のみ。

## 3. 動画構成フレームワーク（HPSC）

広告・プロモーション動画は **Hook → Problem → Solution → CTA** の4幕構成を基本とする。

### 3.1 Hook（冒頭0-3秒）— 全ての成否はここで決まる

**目的:** スクロールを止める。3秒以内に「自分に関係ある」と思わせる。

| やること | やってはいけないこと |
|----------|---------------------|
| ターゲットの痛みを直接突く問い | ブランドロゴから始める |
| 衝撃的な数字・事実 | 「こんにちは」「はじめまして」 |
| 予想を裏切る映像 | 汎用的なストック映像 |
| 「あなたも○○していませんか？」 | 機能の説明から入る |

**テスト基準:** 音声オフ+テロップだけで、3秒後に「続きが気になる」と思えるか。

### 3.2 Problem（3秒-全体の40%）— 痛みを自分ごとにする

- ターゲットの**頭の中の会話（VoC）**をテロップ化
- 「あるある」を2-3個テンポよく並べる
- 放置した場合の痛みを映像で可視化（数字、対比、タイムラプス）
- LP設計SOP §4の原則1（AI美辞麗句禁止）をテロップにも適用

### 3.3 Solution（40%-75%）— 救いを見せる

- 商品を**機能ではなく体験**として見せる
- 「Before → After」の対比が最も効果的
- スクリーンキャプチャを使う場合: 操作の要点だけ。全手順を見せない
- 差別化ポイントを1つだけ強調（詰め込みは逆効果）

### 3.4 CTA（最後の15-25%）— 迷わせない

- 何をすればいいか1文で指示（「プロフィールのリンクから」「概要欄から」）
- ボタン風のビジュアル要素を表示
- URLやQRコードは配信面に応じて（Reels=プロフィール誘導、LP=そのまま遷移）
- 最後のフレームはCTAを3秒以上残す（スクショされる可能性を想定）

## 4. テロップ/コピー品質基準

| # | 基準 | 違反例 → 修正例 |
|---|------|----------------|
| 1 | **AI美辞麗句禁止** — LP設計SOP §4と同一基準。テロップにも適用 | ×「革新的なPOSシステム」→ ○「月額0円。壊れても10秒で復旧」 |
| 2 | **1画面1メッセージ** — テロップは同時に1つだけ。2行以上は分割 | ×3行テロップ → ○1行ずつ順にフェードイン |
| 3 | **文字数制限** — スマホ縦型: 1行15文字以内。横型: 1行20文字以内 | ×「お困りではありませんか？サポートに電話しても繋がらない」→ ○「サポートに電話しても」「繋がらない」（2画面に分割） |
| 4 | **コントラスト確保** — 背景とテロップの色差を十分に取る。白文字+影 or 半透明帯 | ×明るい映像に白文字 → ○半透明黒帯+白文字 |
| 5 | **数字は大きく** — 金額・%・期間は本文より1.5倍以上大きく表示 | ×「月額0円」（同サイズ）→ ○「月額<大>0</大>円」 |
| 6 | **検証可能な事実のみ** — LP設計SOP §4原則3と同一。テロップでも曖昧な実績禁止 | ×「多くの店舗で導入」→ ○「導入200店舗」 |

## 5. 音声/BGM設計

### 5.1 ミュート前提（Instagram Reels/Stories/X/LP自動再生）
- テロップだけで100%伝わる設計が必須
- BGMは「あったら雰囲気が良くなる」程度の役割
- SEは視覚的変化と同期（テロップ出現、画面切替）

### 5.2 音声重視（TikTok/YouTube/YouTube Shorts）
- ナレーションの場合: テロップと完全同期。ズレ禁止
- BGMはナレーションの邪魔にならない音量（-12dB〜-18dB目安）
- 冒頭3秒の音でも注意を引く設計（SE、音楽の出だし）

### 5.3 共通ルール
- フリー素材のライセンス確認必須（商用利用可/クレジット要否）
- BGMのループ処理: 尺に合わせてフェードアウト。ぶつ切り禁止
- 最終フレームは0.5秒かけてフェードアウト

## 6. 競合動画分析（制作前に実施）

### 6.1 収集
- P0 S3の競合リスト+同業種の広告動画を**3-5本**収集
- 配信面が同じものを優先（Reels広告ならReels広告を分析）

### 6.2 分析テーブル

| 観点 | 競合A | 競合B | 競合C | 自社（設計方針） |
|------|-------|-------|-------|-----------------|
| フック（最初の3秒で何をしているか） | | | | |
| 構成（HPSC準拠か/独自か） | | | | |
| テロップの量と質 | | | | |
| 映像素材の種類（実写/CG/テキスト） | | | | |
| 音声戦略（ミュート/BGM/ナレ） | | | | |
| CTAの内容と配置 | | | | |
| 尺 | | | | |
| 再生数/エンゲージメント（取得可能な場合） | | | | |
| **強い点** | | | | |
| **弱い点** | | | | |

### 6.3 差別化方針
- 競合動画の弱い点を自社の強みにする
- フック・構成・CTAのいずれかで明確に差別化する方針を決める
- 分析テーブルの「自社（設計方針）」列を全て埋めてから進行表作成に進む

## 7. 品質チェックリスト（レンダリング前に確認）

| # | チェック項目 |
|---|-------------|
| 1 | **フック3秒ルール**: 音声オフ+テロップだけで、3秒後に「続きが気になる」と思えるか |
| 2 | **HPSC構成**: Hook→Problem→Solution→CTAの順で展開しているか |
| 3 | **AI美辞麗句ゼロ**: テロップにAI臭い表現がないか |
| 4 | **1画面1メッセージ**: テロップが同時に2つ以上表示されていないか |
| 5 | **文字数制限**: 縦型15文字/横型20文字以内か |
| 6 | **テロップ視認性**: コントラスト確保、セーフゾーン内に配置されているか |
| 7 | **CTA明確**: 最後に何をすべきか1文で指示されているか。CTAが3秒以上表示されているか |
| 8 | **プラットフォーム仕様準拠**: 解像度・アスペクト比・尺が§2のテーブル通りか |
| 9 | **音声**: BGM/SEのフェードアウト処理。ナレーション使用時はテロップと同期しているか |
| 10 | **競合差別化**: 競合動画分析テーブルの方針通りに差別化できているか |
| 11 | **LP整合**: テロップの全主張（価格・機能名・数字・条件）が現在のLP記載と一致しているか。動画だけ見て申し込んだ人がLPで「話が違う」と感じないか |
