最重要結論 — できる。ただし価値は「判断層」にあり、FFmpeg と auto-editor はそれを担えない

① 長編→ショート自動化は OSS で既に成立。SamurAIGPT/AI-Youtube-Shorts-Generator（★3.9k）が「download→Whisper転写→LLMハイライト選定→自動クロップ」の8段を実装し、OpusClip 代替を名乗る。アーキテクチャは確立済み。
② FFmpeg は"筋肉"・auto-editor は"無音カット前処理"であり、どちらも「どこを切るか」を判断できない。auto-editor の判断基準は音量/動きの閾値のみ（README原文で確認）。ハイライト選定機能は存在しない。
③ Claude Code（LLM）が埋めるのは"脳"＝ハイライト選定＋オーケストレーション。これは現場が「AIに最も任せられず、かつ最も価値がある」と口を揃える層（FORKOFF「AI surfaces candidates, humans pick finalists」）。
④ 最大の落とし穴は「LLMは正確な秒数を出せない」（imgly原文「LLMs are bad at outputting precise timestamps」）→ LLMには"残すテキスト"を返させ word-level transcript に逆マッチングするのが定石。
⑤ 完全自動は非現実的。AI生成クリップの歩留まりは30〜50%（OmniWeb）、AIオンリー運用は4ヶ月でCPQV 22%劣化（FORKOFF）。勝ち筋は human-in-the-loop。

B. 分析・示唆

  1. 切り出しの第一基準は「単体で完結し、かつ文脈を保つ」。AIが「思考完結前にカット」するのはこの完結性判定が苦手だから＝人間介在の核。
  2. 最初の3秒が定量ゲート。離脱50-60%が3秒以内、intro retention 70%超／3秒保持65%超が拡散の最低ライン。編集はこの3秒に全リソース集中。
  3. カット頻度は2-4秒に1カットが高パフォーマンスの目安、序盤はさらに速く。ただし過剰編集（無限ズーム/whoosh）は逆効果という上限警告も明確。
  4. テロップは「単独でフックになる視覚要素」。burned-in字幕で維持率+15-25%。ミュート視聴前提（音声に頼らない視覚フック）が国内外共通。
  5. 縦型変換の核は「被写体を中央に保持し続ける」。日の丸構図＝Auto Reframeの subject-centering と同思想。静止=Slower／動き=Faster で選ぶ。
  6. 商用ツールは「話者中心コンテンツ専用機」。spoken content（対談/講演）に最適、アクション・音楽中心は不得手と各社明言。
  7. AIの最大の弱点は「文脈喪失」と「テンプレ疲労による同質化」。全ユーザー同一字幕スタイルでアルゴリズム減点、4ヶ月でCPQV 22%劣化。勝ち筋は AI候補→人間決勝選別。

C. 分析・示唆

  1. テロップ工程が編集代行の最大ボトルネック（編集時間の半分）。自動化ROIが最も高いのはカットでも書き出しでもなく「文字起こし→テロップ流し込み→スタイル一括適用」。
  2. 手戻りの構造は"毎回ゼロからデザイン設定"の繰り返し。タイピング速度では解決せず、テンプレ化・マスタースタイル一括適用が業界の実務解。
  3. テキストベース編集（Descript型）が無音・フィラーカットを"秒"に短縮。長尺→粗編集段階の自動化余地が大きい。
  4. 長尺1本からの量産歩留まりは30〜50%。完全自動でなく「AI生成→人手選別・トリミング」のハイブリッドが現実的。
  5. 処理時間そのものは既に高速（30分動画で5〜10分）。律速はAI計算でなく人間の選別・字幕修正・最終チェック。自動化投資はここに向ける。
  6. 単価は二極化。CWのカット+テロップは1,000円前後＝自動化で代替・量産化が進む構造。企画・構成込み（1.5〜3万）は人手価値が残る。

E. 落とし穴（原文根拠付き）

  1. LLMは正確なタイムスタンプを出せない→"残すテキスト"を返させ word-level に逆マッチング（imgly）。
  2. 字幕焼き=再エンコード必須「burning subtitles re-encodes video」。-c:a copy で音声は保てるが映像は必ず再エンコード（mpegflow）。
  3. crop と scale の順序で結果が変わる。中央拡大なら crop 先、縁トリムなら scale 先。
  4. scene検出は確率値でしきい値依存。0.4固定は誤検出/取りこぼし、コンテンツ依存で調整必須（GDELT）。
  5. 9:16中央cropは構図破綻。話者が画面端で見切れる→話者追従(ClipsAI/MediaPipe)が必要。
  6. diarizationに外部トークン依存。WhisperX/ClipsAIの話者分離はPyannote=HuggingFace token必須。
  7. 長尺はchunk分割しないとLLM context超過。>30分は20分オーバーラップ分割+>50%基準dedupe。
  8. 無音除去の精度はしきい値次第。noise=-30dB:d=0.5は環境音で誤判定、手動調整必須。

C. 判定：ショート切り出し用途に使えるか

使えない（長編→縦型ショート自動切り出しツールではない）
auto-editor の自動化対象は「dead space（typically silence）の除去」で、判断基準は 音量(loudness)/動き(motion)の閾値のみ。「内容の面白さ/盛り上がり=ハイライト」を理解する仕組みは一切ない。閾値を下回る区間を機械的に間引くだけ。縦化(9:16・話者追従)機能もなし（--resolution/--scaleは単純設定/拡縮）。
→ auto-editor = 無音/静止区間の自動カット（first pass自動化）ツール。これは「どの区間がウケるか」を判断するハイライト選定とは別物。
ClipsAI原文：「Clips AI is an open-source Python library that automatically converts long videos into clips … resize its aspect ratio from 16:9 to 9:16.」「resizing algorithm dynamically reframes and focuses on the current speaker」github.com/ClipsAI/clipsai README

補足：auto-editor と ClipsAI は競合でなく補完。auto-editor=無音カットで尺を締める前処理、ClipsAI=内容ベース見どころ抽出+縦化。直列に使う設計が合理的。

2. なぜ Claude Code が"効く"のか — 3業界の一致点

  • 映像業界：切り出しの肝は「完結性の判断」。AIが最も外す箇所＝LLMの推論で底上げできる箇所。3秒フック・カット頻度・テロップ設計という"ルール化された判断"はプロンプトに落とせる。
  • 編集業界：最大コストはテロップ工程（編集時間の半分）。文字起こし→テロップ自動投入はLLM+FFmpeg焼きで直撃できる。律速は人間の選別＝Claude Codeが候補を絞れば工数が圧縮される。
  • 開発者業界：パイプラインは既にOSSで枯れている（SamurAIGPT 8段）。Claude Codeは「LLM区間選定＋ffmpegコマンド組立＋失敗時リトライ」を一つのエージェントループで束ねられる＝個別OSSの寄せ集めより統合度が高い。

3. 差別化の鍵 — "テンプレ疲労"を避ける

FORKOFF原文「median AI-only … 22% degradation in CPQV between month one and month four」「all produced the same caption style」。OpusClip等の既製SaaSは全ユーザー同一スタイルでアルゴリズムに減点される。自前FFmpegで字幕デザイン・構図・選定基準を握れば、この同質化を回避でき、ここが自作の最大の競争優位になる。さらに「top-scoredだけ出すと総再生量の40-60%を取りこぼす」＝選定基準を複数走らせる設計に妙味。

4. kosespark 文脈での示唆

本テーマは「Claude Code拡張型 AI統合ツールの構築販売」（kosespark P0コンセプト）の具体ユースケース候補。①既存SaaS(OpusClip月額)の不満＝テンプレ疲労・選定の取りこぼし・縦化の構図破綻、を自作で解く余地が原文で裏取りできた。②「素人がClaude Codeを使える」を検証する題材として、動画編集者という非エンジニア層は相性が良い。③ただし即死仮説検証が先（memory P1）。本リサーチは販売仮説の素材であり、実装着手の承認材料ではない。

5. 最小PoC構成（推奨）

  1. yt-dlp or ローカルmp4 → faster-whisper(word_timestamps=True)で transcript
  2. Claude に transcript を渡し、virality 4軸(Hook/Flow/Value/Trend)で「残すテキスト＋hook文」をJSON返却
  3. 返却テキストを word-level timestamp に逆マッチング→start/end秒を確定
  4. FFmpeg：trim → crop=9:16(話者中央) → subtitles焼き(背景ボックス)
  5. 3本生成→人間が選別（歩留まり30-50%前提）。この選別UIまで作って初めて実用

auto-editor は任意で②の前に無音first passとして挟める（尺圧縮）。必須ではない。
