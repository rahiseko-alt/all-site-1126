Claude Code 導入サポート資料 — 版別統合ガイド

所要：約55〜65分 ／ 対象：プログラミング初心者 ／ 一次情報：https://code.claude.com/docs/ja/

サポート開始前に必ず確認する2点
  1. どの「版」で使うか ＝「ローカルで編集する版（CLI／デスクトップ／VS Code）」か「Web版」か。これで手順2〜5の中身が変わります。
  2. 有料プランを契約済みか ＝ 無料プランでは使えません。Claude Pro（月20ドル）以上、または Anthropic Console の API キー（従量課金）が必要です。
この資料の使い方
  • ローカル系3版（A/B/D）を選んだ場合 → 手順1の該当版＋共通の手順2〜5 を使う
  • Web版（C）を選んだ場合 → 手順1の版C＋Web版の手順2〜5 に差し替えて使う

0. 共通の大前提（全版・先方へ要事前告知）

  • 無料プランでは使えません。 Claude Pro（月20ドル）以上のサブスク契約が必要です（または Anthropic Console の API キーで従量課金）。
  • 機密情報（APIキー・パスワード）はチャットやコミットに貼らない。
  • Claude の提案（特に削除・公開・課金が絡む操作）は必ず人間がレビューしてから採用する。
  • 一次情報は公式ドキュメント https://code.claude.com/docs/ja/。

利用形態（版）の選び方

版ローカルPCのファイル編集手順2〜5向き
A. ターミナル/CLI版する現行のまま共通コマンド操作が得意
B. デスクトップアプリ版する現行のまま共通初心者に最も簡単
C. Web版しない（クラウドVM）Web版2〜5に差し替えローカル環境構築が苦手・プレビュー段階
D. IDE拡張版（VS Code）する現行のまま共通既にVS Code利用中
先方に確認すべきは「ローカルで編集する版か / Web版か」の2択だけ。ローカル系3版は手順1のみ差し替え、Web版のみ手順2〜5ごと差し替えます。

手順1：Claude Code を使える状態にする（版別）

版A：ターミナル/CLI版 所要15〜20分 — 現行プランの想定

出典: https://code.claude.com/docs/ja/setup

  • インストール（Windows PowerShell）：
    irm https://claude.ai/install.ps1 | iex
    （Node.js不要・自動更新あり）
  • 起動：ターミナルで claude
  • 認証：自動で開くブラウザで Claude Pro/Max ログイン（または Console API キー）
  • Git for Windows をオプション導入推奨（Bashツール有効化のため）
  • → 手順2〜5そのまま適用

版B：デスクトップアプリ版 所要10〜15分 — 初心者に最も簡単

出典: https://code.claude.com/docs/ja/desktop-quickstart

  • 公式サイトから Windows 用インストーラーをDL → 起動
  • claude.ai アカウントでサインイン（有料プラン必須）
  • 上部「Code」タブ → Environment を「Local」に → プロジェクトフォルダを選択
  • Windows は Git のインストールが必須
  • → 手順2〜5そのまま適用

版C：Web版 所要10分 — ローカル環境構築が不要・※プレビュー段階

出典: https://code.claude.com/docs/ja/claude-code-on-the-web

  • ブラウザで https://claude.ai/code → 有料プランでサインイン
  • 左サイドバー「Code」→ GitHubリポジトリ連携（GitHub App 認可が必須）
  • 実行環境は Anthropic のクラウドVM上に自動構築
  • ⚠️ ローカルPCのファイルは編集しない／GAではなくリサーチプレビュー段階
  • → 手順2〜5は「Web版 手順2〜5」に差し替え

版D：IDE拡張版（VS Code） 所要10〜15分 — 既にVS Code利用中なら

出典: https://code.claude.com/docs/ja/vs-code

  • VS Code（1.98以上）で拡張機能「Claude Code」を検索 → Install
  • 右上の Spark アイコン → Sign in → ブラウザで認可
  • → 手順2〜5そのまま適用

手順2〜5（ローカル系3版＝A/B/D 共通）

元の手順を踏襲。版A／B／D を選んだ場合はこちらを使います。

手順所要内容
手順2 開発環境を整える10〜15分Python・VS Code・ターミナルの基本確認
手順3 Git を初期設定する10分git の初期化／.gitignoreで公開不可ファイル除外／最初のコミット
手順4 プロジェクト管理の枠組みを作る10分フォルダ構成・メモ書きの雛形・設定ファイルの分離
手順5 重要な情報の管理方法を整える10分.env ファイルの使い方ルール（ローカル保存・.gitignoreで除外）

Web版 手順2〜5（版C 専用差し替え）

版C（Web版）を選んだ場合は、上の共通手順2〜5の代わりにこちらを使います。ローカルにPython・VS Code・git を入れる必要はありません。

Web版 手順2：利用環境とリポジトリを用意する 10分

目的：ローカルのPython/VS Code/ターミナルの代わりに、クラウド側で動かす準備を整える

  • GitHubアカウントを用意（必須）
  • 新規プロジェクトの場合：先に https://github.com/new で空のリポジトリを作成してから Web版を開く
  • ブラウザで https://claude.ai/code →「Code」→ 対象リポジトリを選択
  • ⚠️ ローカルPCへの Python・VS Code・ターミナル導入は不要（クラウドVM上で動く）

Web版 手順3：環境（Environment）を作成する 10分

目的：クラウドVMの動作条件を設定する（ローカルの git init に相当）

環境作成画面で4項目を設定：

項目設定内容
Name任意の環境名
Network accessTrusted 推奨（npm・PyPI 等の取得を許可。遮断なら None）
Environment variablesAPIキー等（→ 手順5）
Setup script依存パッケージのインストールコマンド等（任意・初回のみ実行されキャッシュ）

⚠️ git の初期化・コミットは Claude が自動で行う（→ 手順4）

Web版 手順4：作業とコミットの流れを理解する 10分

目的：中断・再開しても続きから進められる仕組みを理解する

  • タスク送信 → リポジトリがVM上にクローン → 新しいブランチ自動作成 → Claudeが編集 → GitHubへ自動push
  • ⚠️ ユーザーが手動で commit / push する操作はない（全自動）。ユーザーは diff ビューでレビュー → インラインコメント → PR作成
  • セッション履歴はサイドバーに残り、中断・再開できる
  • ⚠️ pushされていないVM上のファイルはセッション終了で消える＝GitHubに入ったものだけが残る（リソース上限：4vCPU / 16GB / ディスク30GB）

Web版 手順5：重要な情報（APIキー等）の管理 10分

目的：APIキーやパスワードを安全に渡し、誤公開を防ぐ

  • 環境作成時の Environment variables に .env 形式で入力： 
    OPENAI_API_KEY=sk-xxxxxxxx
DATABASE_URL=postgres://user:pass@host:5432/db
    ⚠️ 値はクォートで囲まない（囲むとクォート文字も値に含まれる）
⚠️ 公式記載の制約2点（要告知）
  1. 環境変数は平文で保存され、その環境を編集できる人は全員閲覧できる → 機密を入れる環境は信頼できるメンバーのみに限定
  2. 専用の Secrets 機能はまだ提供されていない（環境変数フィールドが現状の唯一の手段）
  • コードに直書きせず process.env.OPENAI_API_KEY / os.environ[...] 経由で読む
  • .env をリポジトリ内に作る運用も可だが、必ず .gitignore に .env を入れて誤コミットを防ぐ

共通（全版）

注意事項
  • 無料プランでは使えない。Pro（月20ドル）以上の契約を継続する。
  • APIキー・パスワード等の機密はチャット／コミットに貼らない。漏洩経路の最大は「貼付」。
  • 削除・公開・課金が絡む操作は必ず人間が最終確認してから実行する。
日々の使い方の区切り
  • ローカル系：作業の区切りで git commit（戻せる状態を残す）。
  • Web版：レビュー → PR で GitHub に反映（push前のVM内変更は消える）。

ローカル系版（A/B/D）固有

  • ネイティブインストーラー版は自動更新。npm版は claude update 等で手動更新。
  • CLI版はターミナルで claude 起動 → 作業 → 区切りで commit。デスクトップ/VS Code拡張はGUIで完結。
  • ローカルに置いた .env は必ず .gitignore で除外（公開リポジトリへの誤push防止）。

Web版（C）固有

  • セッション終了でpush前のファイルは消える → 重要な変更は必ずPRでGitHubに反映。
  • 環境変数は平文保存・閲覧注意。機密は信頼メンバー限定の環境に。
  • 大規模ビルド／メモリ集約タスクはリソース上限（4vCPU/16GB/30GB）で失敗しうる。
  • リサーチプレビュー段階のため、仕様が変わる可能性がある（公式docを随時確認）。
