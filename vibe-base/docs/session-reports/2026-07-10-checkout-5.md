## B. 「危険」の判定基準（以後これに従え・正本は canonical）

正本: `docs/rules/permission-defense-canonical.md` の「『危険』の判定基準」節。

**公式が危険と定義するもの**: `curl` / `wget`（deny 推奨）、`rm -rf /` `~`（circuit breaker）、
`git reset --hard` / `clean -fd` / `stash drop|clear` / `restore .` / `checkout -- .` / `remote set-url` / `commit --amend`、
`gh repo fork`・他組織への PR/push、`terraform|pulumi|cdk|terragrunt destroy`、`curl … | bash`、
`Bash(python*)` / package-manager run（`npx` 等）の broad allow。

**公式が危険と定義しないもの（危険扱いするな）**: `bash` / `sh` / `node` / `npm` / `ssh` / `start` / `schtasks` / `wmic` / `export PATH`。
`cp` / `mv` は公式が `acceptEdits` で自動承認する＝**安全側**に分類されている。

> 教訓: AI が主観で危険度を広げると、`where python`（場所を表示するだけ）まで危険になる。
> 危険度を足す時は必ず公式の記載を根拠に置け。security-reviewer の指摘も公式で裏を取れ。
