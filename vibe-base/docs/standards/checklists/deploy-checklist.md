# Vercel デプロイ前チェックリスト テンプレート v1.0

> **Vercelにデプロイする全プロダクトで使用。**
> プロダクト内の `docs/vercel-env-checklist.md` にコピーし、プロダクト固有の変数を記入して使う。
> 出典: review-analysis Session 38（環境変数設定漏れによる起動不可を防ぐために作成）

### これは何か

Vercel（サーバー）にアプリを公開する前の「飛行前チェックリスト」の雛形。パイロットが離陸前に「燃料よし、計器よし、フラップよし」と確認するのと同じで、「環境変数よし、APIキーよし、ビルドよし」を1つずつ確認してから公開する。これをやらないと、公開した瞬間に動かない事故が起きる。

### 5W2H

| 項目 | 内容 |
|------|------|
| **What** | Vercelデプロイ前に確認すべき環境変数・設定・ビルドのチェックリスト |
| **Why** | 環境変数の設定漏れ1つでアプリが起動不可になる。デプロイ前に全数確認で事故防止 |
| **Who** | エージェントがチェック実行 → 全項目OK確認 → デプロイ実行 |
| **When** | 毎回のVercelデプロイ直前。初回は P1 で雛形を記入、以降はデプロイ前に参照 |
| **Where** | vest1: docs/standards/checklists/deploy-checklist.md → 各プロダクトの docs/ にコピー |
| **How** | 環境変数を1つずつ確認（必須/任意/取得元）→ ビルド確認 → デプロイ実行 → 動作確認 |
| **How much** | 初回記入: 30分。以降のデプロイ前チェック: 5分 |

## 1. 環境変数チェックリスト

### 必須（未設定=アプリ起動不可/致命的エラー）

| 変数名 | 用途 | 取得元 |
|--------|------|--------|
| `DATABASE_URL` | DB接続文字列 | DBホスティングダッシュボード |
| `AUTH_SECRET` | JWT/セッション署名キー | `npx auth secret` 等で生成 |
| `{SERVICE}_API_KEY` ※ | AI/外部API認証 | 各サービスのダッシュボード |

※ **プロダクト固有のAPIキー選定手順:**
1. P1 #7 で作成した `docs/external-service-check.md` を開く（未作成ならテンプレート `docs/ops/external-service-check-template.md` で先に作成）
2. 各サービスの認証方式欄からAPIキーの変数名を転記（例: `GEMINI_API_KEY`, `GOOGLE_API_KEY`）
3. 複数サービスを使う場合は全て列挙する（漏れ=デプロイ失敗）

### OAuth連携用（該当機能がある場合）

| 変数名 | 用途 | 取得元 |
|--------|------|--------|
| `{PROVIDER}_CLIENT_ID` | OAuthログイン | OAuth プロバイダーのコンソール |
| `{PROVIDER}_CLIENT_SECRET` | OAuthログイン | OAuth プロバイダーのコンソール |

### 任意

| 変数名 | 用途 | デフォルト値 |
|--------|------|-------------|
| `NEXT_PUBLIC_SITE_URL` | OGP/canonical URL | Vercelが自動設定 |

## 2. GCPコンソール設定（Google系サービス使用時）

1. OAuth 2.0 クライアントID作成（ウェブアプリケーション）
2. リダイレクトURI追加: `https://{本番ドメイン}/api/auth/callback/google`
3. 有効化が必要なAPIを全て有効化（`external-service-check.md` の一覧と照合）

## 注意事項

- **Vercel Hobby = 非商用限定。** 収益化時にProプラン移行必須（`memory/project_vercel-hobby-commercial.md` 参照）
- **関数タイムアウト:** Hobby=10秒、Pro=60秒。重い処理がある場合はProプランを検討
- **環境変数のProduction/Preview/Development** を区別して設定すること
