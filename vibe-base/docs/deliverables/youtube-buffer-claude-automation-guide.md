# YouTube企画「ClaudeとBufferを連携させて複数SNSを自動投稿しよう」— STEP4〜6 実演手順書

> STEP1〜3（Bufferとは／なぜ連携するのか／今回の概要）は台本担当外。本書はSTEP4〜6のみ。
> 対象チャンネル: **X（kosehirax）・Threads（kosehira.threads）のテキスト投稿のみ**。画像は今回スコープ外のため画像必須のInstagramは対象外。

## 設計原則（本書の構成ルール）

人間の台詞とAIへのプロンプトは**必ず対で書く**。プロンプトは2種類あり、混同すると収録事故になる。

| 種別 | AIにさせること | この手順書での扱い |
|---|---|---|
| **実行型** | AIに実際にやらせる（API呼び出し・文章生成など） | 既に実機で検証済みのプロンプトのみ掲載。結果も実データを併記 |
| **ナビ型** | AIは**手順を教えるだけ**。実行は人間（シークレット絡み・AIが安全にできない操作） | クリックする場所を①②③で具体的に書く。AIに"実行"を求める書き方はしない（悪い例＝「設定しといて」と丸投げしてAIがシークレット拒否で止まる） |

シークレット（APIトークン等）が映る画面は**収録では絶対に映さない・ズームしない**。本書作成中に「環境変数欄が平文表示される」仕様を実機で確認済み（Buffer側のキー一覧は末尾4桁のみのマスク表示だが、claude.ai Cowork側の環境変数編集画面はマスクなし）。

## STEP4: まず連携しよう

### ④-a 【人間】「BufferのAPIキーを発行しましょう。取り方をAIに聞いてみます」

【AIへのプロンプト・ナビ型】
```
Bufferの管理画面でAPIキーを発行する手順を、クリックする場所ごとに教えて
```

【AI出力（実機で実際に踏んで確認済み・2026-07-19）】

⚠️ **この収録アカウントは既にSTEP6の本番routineでキーを1個使用中。無料プランは上限1〜数個のため、「+ New Key」はほぼ確実にアップグレード要求画面に当たる。台本の主軸は①〜③（既存キー流用）にし、④⑤（新規発行）は「もし枠が空いていたら」の補足に留める。**

```
① publish.buffer.com にログイン
② 左サイドバー下の方「Other」セクションにある「API」をクリック
③ 「Personal Keys」タブ（デフォルトで開いている）に、既に使用中のキーが
   1件表示されている。行のコピーアイコン（帳票アイコン）でキー値をコピー
　　（＝収録本番はここで完結する想定）

　　※ 補足（枠が空いている場合のみ）: 右上「+ New Key」で新規発行も可能。
　　　上限に達していると「Upgrade to do more with Buffer's API」という
　　　アップグレード要求画面が出てフォームに到達できない。
④ コピーした値は**画面に貼らず**、ローカルのテキストファイル等に保存する
```

### ④-b 【人間】「保存できたら、Claude Codeに実際につないでみましょう」

【AIへのプロンプト・実行型】
```
保存したBufferトークンで接続テストして、登録済みチャンネル一覧を見せて
```

【検証済み実行結果（実機確認済み）】
```
6a5705b280cc80cdcab7f6b4 | twitter  | kosehirax          | disc=false
6a57413d80cc80cdcab9f216 | instagram| kosehira_ig        | disc=false
6a572d3280cc80cdcab96596 | threads  | kosehira.threads   | disc=false
```

→ 3チャンネルが即座に返る。「もうClaude CodeがBufferの中身を見えている」ことを視覚的に示せる。トークンは読み込むだけでstdoutに一切出力しない設計（安全な実装であることを明言できる）。

## STEP5: 投稿内容を生成させよう

### ⑤-a 【人間】「投稿のルールを教えて、AIに考えてもらいましょう」

【AIへのプロンプト・実行型（純粋な文章生成＝確実に動く）】
```
以下のルールでX向けの投稿文を1本、日本語で作って。

- 40〜140字、ですます調、二人称は「御社」
- URL・絵文字・ハッシュタグ・@メンションは使わない
- 「絶対・100%・必ず・最強」等の誇大表現は禁止
- 題材は中小企業の業務改善・生産性・AI活用の実務Tips
- 末尾は「御社の◯◯は？」型の問いかけで締める
```

【検証済み生成例（実機確認済み）】
```
AI活用の第一歩は、議事録の自動要約から始める企業が多いです。手間のかかる会議メモ作成、御社では誰が担当していますか？
```

### ⑤-b 【人間】「できた文章を、実際にBufferへ登録させましょう」

⚠️ 「今生成した」という指示語は、収録でNG出し・撮り直しを挟むと参照先がズレる。**本番では生成文をその場で読み上げて確定させてから、以下のように文章そのものを貼って渡す。**

【AIへのプロンプト・実行型】
```
次の投稿文を、Bufferのkosehirax（X）チャンネルに下書き（draft）として登録して。

「（⑤-aで確定した投稿文をここに貼る）」
```

【検証済み実行結果（実機確認済み）】
```json
{
  "data": {
    "createPost": {
      "__typename": "PostActionSuccess",
      "post": { "id": "6a5cb8655465343a82658bc2", "status": "draft", "text": "..." }
    }
  }
}
```

→ `PostActionSuccess` が返り、Buffer管理画面のdraft一覧に実際に表示される。**下書きなので公開されない＝収録事故のリスクなし。**

### ⑤-c 収録後の後片付け

テスト用draftは削除可能（実機確認済み・`DeletePostSuccess` 応答）。収録で作ったdraftを残したくない場合は、⑤-bの応答に出た `post.id` を指定して「post id ○○のdraftを削除して」で消せる（「今登録した」だけだと撮り直し後にどのdraftか曖昧になるため、idを明示する）。

## STEP6: 投稿と補充を自動化させよう

### 概念（視聴者向け解説）

STEP4・5は「Claude Code（ローカルCLI）に1回頼んで1回実行」。STEP6は主役が変わる。**claude.ai の Cowork（クラウド側のルーティン機能）に仕組みを置き、以後はPCもClaude Codeの起動も不要で、決まった時間に自動的に投稿文が生成されBufferに供給される**状態を作る。

この分担は実際にこの仕組みを最初に作ったとき（2026-07-16）と同じ構造で成立している:
- **シークレットが絡む部分（環境変数登録）＝人間がUIで行う**（AIはシークレットを直接扱えない）
- **routine自体の作成＝AIが実行できる**（Claude Codeが `schedule` スキル／Remote Trigger機能を通じてclaude.aiのルーティンAPIを操作する。これは素のClaude Codeが誰でも最初から持っている機能ではなく、この専用の仕組みを介して初めて可能になる点は視聴者に一言添える）

### ⑥-a 【人間】「クラウド側にトークンを渡す場所を作ります。ここはAIじゃなく手でやります」

【ナビ型（AIに手順だけ聞く）】
```
claude.aiのCoworkで、Bufferトークンを使えるクラウド環境を新規作成する手順を教えて
```

【手順（実機で確認済み・2026-07-16構築時の設計＋本書作成時の画面遷移で再確認）】
```
① claude.ai/code を開く
② 左サイドバー「ルーティン」を開く
③ 新規routine作成 or 既存routineの「...」メニュー→「環境を編集」
④ 「環境変数」欄に .env 形式（クォートなし）で1行入力:
   BUFFER_API_TOKEN=<STEP4でコピーしたキー>
⑤ 「ネットワークアクセス」を「カスタム」にし、
   許可ドメインに api.buffer.com を追加
⑥ 保存
```

⚠️ **収録上の最重要注意**: ④の環境変数入力欄は**平文表示**される（Buffer側のキー一覧のようなマスクがない）。この画面は**収録カメラに映さない・ズームしない**。事前収録の別カットに差し替えるか、音声解説のみで済ませる。

### ⑥-b 【人間】「環境ができたら、実際にroutineを作ってもらいましょう」

⚠️ **本ブロックは未検証（ナビ型相当の想定手順）。** ⑥-aで作った環境名をAIは知らないため、「今作った」ではなく環境名を明示する。また実際にroutineを新規作成する操作は本書作成セッションでは実行していない（読み取り＝`get`のみ検証済み・`create`は未実施）。**収録前に一度リハーサルで実行し、結果を実データに差し替えること。**

【AIへのプロンプト・実行型（想定・要事前リハーサル）】
```
cloud environment「（⑥-aで名前欄に入力した環境名をここに書く）」を使って、STEP5と同じルールで
投稿文を生成しBufferのkosehirax（X、channelId 6a5705b280cc80cdcab7f6b4）へdraftとして登録する
routineを新規作成して。トリガーはまだ付けず、作成だけして。
```

【期待される結果（未検証）】routineが作成され、"Run now" で手動実行できる状態になる。

### ⑥-c 【人間】「試しに1回動かして、うまくいったら毎日自動で回すようにしましょう」

⚠️ 本ブロックも未検証。routine名または `RemoteTrigger` のtrigger_idを明示して参照する（「今作った」だと撮り直し後に曖昧になる）。

【AIへのプロンプト・実行型（想定・要事前リハーサル）】
```
⑥-bで作成したroutineを一度実行して、Bufferにdraftが登録されるか確認して
```

確認できたら、本番化とcron付与は**別の【人間】【AIプロンプト】として明示する**（地の文で済ませない＝ここが一番の事故ポイント）:

【人間】「うまくいきましたね。ではこれを毎日自動で回るようにします」

【AIへのプロンプト・実行型（不可逆・マスター明示GOの後のみ実行）】
```
⑥-bで作成したroutineの下書き設定（saveToDraft）を外して本番化し、毎日1回のcronトリガーを付与して
```

→ **この操作は不可逆＝実際に公開アカウントへ投稿される。収録中にマスターの明示GOを得てから実行する。**

### 実例として見せる（本番で実際に毎日稼働中・視聴者への説得材料）

```
routine名（claude.ai画面表示）: buffer-refill-x-kosehirax
routine ID: trig_01WuxHeHMYZDxqV2iMtmVPGZ
cron: 0 3 * * *（= 毎日 日本時間 12:00）
```

このroutineは実際に日次でX・Threads向けの投稿文を生成し、Bufferキューへ自動供給している（2026-07-16稼働開始）。

**表記の出典に注意**: 過去のsession-reportにはIDでしか記録がなく、表示名「buffer-refill-x-kosehirax」は本書作成セッションでclaude.aiのルーティン一覧画面を直接開いて確認した実物の表示名。収録直前に一度画面を開いて名称が変わっていないか確認すること。

### 収録上の注意（まとめ）

- **⑥-b・⑥-cの新規routine作成〜実行は未検証。収録前に必ず1回リハーサルし、実際の出力に差し替える**（新規のcloud environment・routineを作る前提。既存本番routineでは試さない）
- ⑥-aの環境変数入力画面は映さない
- 本番化・cron付与（⑥-c後半）は収録中にマスターの明示GOを得てから実行する
- 動画内では「今動いている実例」の画面共有＋「新規作成の手順」の解説の2本立てで見せるのが最も事故が少ない

### 補足: STEP5・STEP5の生成サンプルについて

STEP5-aの生成例・STEP5-bのpost.idは1回限りの生成結果であり、収録本番では毎回異なる文章・異なるIDが出る。台本上の文言と収録本番の出力が一致しないのは正常な挙動である旨、視聴者向けテロップ等で一言添えるとよい。
